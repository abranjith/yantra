## Agent Runtime

**Combined Web Research Tool** _(updated: 2026-07-19 by fix — evidence ledger: fetched sites become the published Brief's sources automatically)_
Source spec: [feature_combined_web_research.md](.spec-lite/features/feature_combined_web_research.md)
The agentic `web_search` tool now returns _evidence, not pointers_: one call runs the provider search, then fetches and extracts the top-N hits through the same `@yantra/core` per-source path the deterministic pipeline uses (`webResearch` over `processSource`), returning strongly-typed per-site content — `{ sites: [{ n, url, title, published_at, excerpt, text | capture_ref }], more_results: [{url,title,snippet}], failures: [{url, stage, reason}] }`. How many hits are fetched inline is set by `search.fetch_top` in `config.yaml` (integer 1–5, default 3; out-of-range fails loud at startup) and can be lowered per-call via `limit`; the unfetched tail is returned as snippet-only "more results". Every fetched URL passes the outbound URL policy and ethics gate individually — a per-URL refusal or fetch/extract miss becomes a per-site `failures` entry (stage `blocked`/`fetch`/`extract`), never a whole-tool error; the top-N fetches run in parallel so wall time stays ≈ one fetch round. Both snippets and fetched page content are untrusted input, sanitized and byte-bounded before the model sees them; oversized site text is stored as a `runs/<id>/captures/<ref>.txt` (mode 0600) capture reference. `web_fetch` is kept but narrowed to fetching one specific URL you already have (a direct link or one found inside fetched content). Every site either tool returns is also recorded in the run's **evidence ledger** (URL, title, excerpt, fetch/publication timestamps — sanitized and bounded at append), which `result_publish` attaches as the Brief's sources with excerpts, so the model never round-trips URLs through its own context. Per-command tool-call caps drop accordingly — ask 12 total / 6 per-tool, research 30 / 12, do keeps the global defaults (ask < research < do preserved) — and the default per-tool execution timeout rises to 60s to cover the search-plus-parallel-fetch round.

**Agentic Ask & Research Convergence** _(updated: 2026-07-20 by fix — flow-aware Interaction line (agent-v3), explicit per-command profile resolution)_
Source spec: [feature_agentic_ask_research.md](.spec-lite/features/feature_agentic_ask_research.md)
`yantra ask`, `yantra research`, and `yantra do` now use the same `runAgenticTask` lifecycle, `agent-v3` system prompt (a flow-neutral **Completion and failure** rule — never stall waiting for input: interpret a broad goal with the most reasonable interpretation and proceed; the per-run user prompt then carries the flow-specific `Interaction:` line — an unattended run states no user can answer, while an attended interactive `do` run (TTY, non-`--json`) states a user is present to approve protected actions but cannot answer open-ended questions — and injects an engine-derived **ambient context block** — current date with weekday, IANA timezone with DST-correct UTC offset, and locale, from the orchestrator's injectable clock and host environment, framed as authoritative so small local models don't answer date-sensitive goals from their training prior; user location is never inferred automatically — it belongs in the approved profile context), run-local session/audit artifacts, tool-call projection, usage ledger, and validated `result_publish` Brief contract whenever LLM reasoning is enabled. `CommandTaskProfile` applies registration-time least privilege: ask is web-only with workflow listing, research gets multi-source completion criteria and optional read-only browsing (`YANTRA_AGENT_RESEARCH_BROWSE=1`), while do keeps its full prior catalog. Each command resolves its profile explicitly at the CLI boundary, so `do` — like ask and research — honors its `YANTRA_AGENT_DO_*` budget env overrides instead of relying on the runtime's implicit default. A stuck-loop circuit breaker ends a run with a diagnostic `AGENT_TOOL_FAILED` after four consecutive identical tool failures (same tool + error code, no success between), so a weak model can no longer spend the whole budget retrying an impossible action. Per-command budget keys (`YANTRA_AGENT_{ASK|RESEARCH|DO}_{BUDGET_MS|MAX_TOOL_CALLS|MAX_CALLS_PER_TOOL}`) configure the caps; tool-call caps preserve ask < research < do defaults, while the agentic wall clock is **unlimited by default** for every command (local models are slow) and is bounded only by an explicit `--budget-ms` flag or `BUDGET_MS` env override — the CLI no longer clamps or injects the deterministic pipeline's timeout into agentic runs. `--no-llm` and `LLM_PROVIDER=none` select the existing deterministic ask/research paths before agent construction, retaining their artifact and golden-output contracts without credentials. The obsolete synthesis, research, client, and plan prompt stacks are removed and kept absent by boundary tests.

**Deterministic Workflow Tool & Promotion** _(updated: 2026-07-14 by implement)_
Source spec: [feature_agent_workflow_bridge.md](.spec-lite/features/feature_agent_workflow_bridge.md)
Bridges the agent runtime and the deterministic workflow engine both ways. **Forward:** a `workflow_run` agent tool discovers saved workflows (`mode:list` returns a secret-free catalog — name/description/params/hosts only, never secret names/values, locator internals, or profile paths, via `WorkflowStore.listCatalog()`) and invokes one (`mode:run`) through the existing `RunOrchestrator`. Run mode validates the workflow exists (`WORKFLOW_NOT_FOUND`) and its params against declared types (`WORKFLOW_PARAM_INVALID` naming the param), then replays deterministically in its **own nested run directory** with no LLM inside; the sanitized, bounded result returns terminal status, step count, an outputs summary, and the nested `run_id`, which the parent's `tool-calls.jsonl` records as the audit join key. Confirmation checkpoints inside the workflow use the FEAT-026 connector bridge; non-interactive surfaces fail closed. **Backward:** every successful browser interaction (navigate/click/fill/extract) is appended to a run-scoped trace (candidate-chain locators from the observation — never opaque refs; secret _references_ for secret fills, never values; confirmation flags), written to `runs/<id>/trace.json` at finalize. `yantra do --save-as <name>` promotes that trace into a saved, lint-clean, replayable workflow (secret fills become declared `{{ secret:key }}` references; `requires_confirmation` flags preserved); promotion failure is reported but never fails the run. A real-Chrome e2e proves the full round-trip: a fake-agent run's trace promotes to a workflow that `yantra run` replays green with no LLM, and an agent scripting `workflow_run` invokes a saved workflow whose nested run carries zero agent-session artifacts.

**Agentic Task Orchestrator & `yantra do`** _(updated: 2026-07-20 by fix — agent-v3 flow-aware prompt, explicit `do` profile, repeated-failure circuit breaker)_
Source spec: [feature_agentic_task_orchestrator.md](.spec-lite/features/feature_agentic_task_orchestrator.md)
`yantra do "<goal>"` now creates one auditable run and one fresh provider session, then lets the agent reason through only Yantra's policy-wrapped web, browser, script, and publication tools. The agent runtime—not the CLI—owns the governed `agent-v3` prompt, budgets, completion nudge (a user-turn message built from run state: it names `result_publish` and its `{"brief": ...}` payload explicitly, recaps the consulted sources from the evidence ledger inline with a do-not-search-again instruction, anchors the model's previous message as the draft to publish, and — when the ledger is empty — states that no user is available so a broad or ambiguous goal is NOT a blocker; at nudge time with evidence in hand the runtime also **freezes the evidence phase**, so further `web_search`/`web_fetch` calls are rejected with `EVIDENCE_FROZEN` and the nudge turn is structurally publish-only; the manifest schema accepts every shipped `prompt_version` so older run artifacts keep validating), fail-closed confirmation bridge, event fan-out, typed outcomes, and exactly-once teardown; success requires a validated `result_publish` Brief. If the nudge turn still ends unpublished but the run holds both a draft answer and ledger evidence, the runtime **assembles and publishes the Brief itself** (draft as overview, ledger as sources with excerpts, `deterministic_fallback_used: true` plus an honest `notices` entry) and the run completes as published. Only when there is no draft or no evidence does the run fail: the `AGENT_COMPLETION_MISSING` failure carries a bounded, whitespace-collapsed excerpt of the model's post-nudge message (its self-stated blocker) into the CLI error and `report.md`, the **full** unvalidated final response is salvaged to `runs/<id>/result.md` (best-effort; noted in the failure message; not a validated Brief — the run still fails), and manifest/`events.jsonl` classify the failure as `validation_error` (consistent with the report) rather than `unexpected`. Terminal output streams bounded progress and compact tool status, while `--json` emits NDJSON and never prompts. The former discovery proposal/session/re-prompt stack and CLI-owned propose/act/observe loop are removed. Deterministic real-Chrome release scenarios cover publication, consented forms, CAPTCHA handoff, denial/timeout/non-interactive confirmation, prompt injection, off-policy fetches, and credential-shaped URL exfiltration; a live-provider scenario remains opt-in.

**Safe Web & Utility Tools** _(updated: 2026-07-19 by fix — result_publish sources are ledger-authoritative)_
Source spec: [feature_agent_web_tools.md](.spec-lite/features/feature_agent_web_tools.md)
Yantra exposes four registered agent tools — `web_search`, `web_fetch`, `script_run`, and `result_publish` — each wrapped by a **mandatory middleware pipeline** the model cannot bypass: closed-schema input validation (violations return `INVALID_INPUT` naming the failing field's JSON pointer) → budget/timeout/abort → host/ethics/scope policy (+ post-publish action-phase latch) → confirmation gateway → domain op (AbortSignal threaded) → sanitizer + per-result byte bounding → stable tool result → audit projection. Expected failures return stable `error_code`s with a `retryable` flag; unexpected exceptions are genericized to `TOOL_EXECUTION_FAILED` with no secret/raw-content leak; sanitization and confirmation are not agent-callable. A run-scoped `BudgetTracker` enforces total/per-tool calls, per-tool timeout, per-result and cumulative agent-visible bytes, navigation/host caps, and an **opt-in** wall-clock cap (unlimited by default; bounded only via `--budget-ms`/`YANTRA_AGENT_<CMD>_BUDGET_MS`); the outbound-URL policy length-caps, https-restricts, credential-shape-scans (`sk-`/`ghp_`/`AKIA`/`eyJ…`), and host-budgets every fetch URL, auditing every decision. `web_search` is now a combined search-that-fetches tool (see **Combined Web Research Tool**) returning per-site extracted content plus a snippet-only tail and per-site `failures`, not just `{url,title,snippet}` pointers; `web_fetch` (narrowed to fetching one specific already-known URL) runs the ethics gate (robots/blocklist/rate limit — no evasion path), a content-type allowlist, and a streamed size limit, fetches through the same hybrid HTTP→headless-browser fallback as deterministic ask/research (bot-refused 401/403 responses and script-rendered shells escalate to a browser render instead of failing), returns `EXTRACTION_EMPTY` with fetch-a-specific-article-URL guidance when Readability finds no article (index/hub/media pages), and stores large extracted content as a `runs/<id>/captures/<ref>.txt` capture reference; `script_run` executes only code-defined, allowlisted transformation scripts (`table_normalize`, `dedupe_lines`, `json_pick`) with validated args out-of-process (worker with time/memory/output caps — trust boundary is the registry, not OS sandboxing); `result_publish` accepts agent-authored content — `{title, overview, key_findings}`, with `title` (non-empty) and `overview` **schema-required** so a payload missing them is rejected as `INVALID_INPUT` naming the field before the publisher runs — and deterministically assembles the formal protocol Brief around it (document/task ids, contiguous source numbering, hosts, fetch timestamps, `synthesis: 'llm'` metadata with the owning run id); **sources are ledger-authoritative**: when the run's evidence ledger has entries (every site `web_search`/`web_fetch` returned), those entries become the Brief's sources with excerpts in consulted order, model-supplied `sources` are ignored, and findings are published as editorial commentary (ad-hoc citation numbers are stripped rather than mis-attributed); model-supplied sources are honored, with full citation-integrity validation, only when the ledger is empty (for example browser-only runs); a complete protocol Brief (detected by `brief_id`/`schema_version`) still passes through untouched for internal callers. Either shape is validated against the protocol schema (citation integrity included; uncited findings default to editorial commentary, an explicit `editorial: false` without citations is rejected), then `brief.json/md/html` are written and the action phase closes (exactly one successful publication — a second attempt is `ALREADY_PUBLISHED`, later mutating calls are `ACTION_PHASE_CLOSED`, read tools stay available). `createYantraTools(runServices)` registers the tools with unique names in deterministic name-sorted order (feeding a stable `tool_catalog_hash`); Pi built-in `bash`/`read`/`write`/`edit`/`grep`/`find`/`ls` tools are asserted absent from the active catalog.

**Run-Local Sessions, Events & Audit** _(updated: 2026-07-16 by fix)_
Source spec: [feature_agent_run_persistence.md](.spec-lite/features/feature_agent_run_persistence.md)
Every agentic attempt owns one movable run directory created before provider, model, or credential validation; startup failures remain visible with a typed manifest error, `task_failed` event, and `report.md`. The manifest records provider/session provenance, relative raw-session location, prompt hash, and canonical tool-catalog hash without credential material. Sanitized tool activity is projected into crash-safe, sequence-ordered `tool-calls.jsonl`, where interrupted calls remain explicitly incomplete, while partial token and cost usage is retained for completed, failed, and aborted runs. `report.md` renders agentic runs from the stable projection: session metadata (provider/model/adapter/auth source), a per-call tool timeline from `tool-calls.jsonl` (status, error code, duration; starts without ends marked `incomplete`), agent usage, and the actual audit-file list including the raw session path — deterministic workflow runs keep the legacy step-timeline report. `yantra audit <run-id>` renders the stable projection, confirmation linkage, usage, and terminal outcome without parsing provider-private session JSONL.

**Executable Agent Provider Foundation** _(updated: 2026-07-16 by fix)_
Source spec: [feature_agent_provider_foundation.md](.spec-lite/features/feature_agent_provider_foundation.md)
Yantra can open a real agent session through a thin `AgentProvider`/`AgentSession` seam backed by the pinned `@earendil-works/pi-coding-agent@0.80.6` SDK (confined to `packages/agent/src/adapters/pi/`; dependency direction is now `protocol → core → agent → cli`, boundary-tested in three layers). Sessions run against **pinned, Yantra-owned Pi paths** (`<data-dir>/pi/` for auth/models, in-memory settings, zero ambient extensions/skills/prompts/context files — a personal pi `auth.json` is an explicit `agent.pi_auth_path` config opt-in) with built-in Pi tools disabled and only registered Yantra custom tools allowlisted. Events crossing the seam (`tool_started`/`tool_finished`/`assistant_text`/`turn_finished`/`failed`) are normalized and pass the core sanitizer; the provider session JSONL is created directly under `runs/<run-id>/agent/` with restrictive permissions. Credentials resolve from the managed store, a runtime-only key from a Yantra secret reference (never persisted or logged), or provider env vars — with the resolved source reported for run-manifest auditing. Startup problems are typed, actionable failures (`AGENT_MODEL_NOT_FOUND`, `AGENT_AUTH_UNAVAILABLE`, `AGENT_PROVIDER_UNAVAILABLE`, `AGENT_SESSION_START_FAILED`, `AGENT_ABORTED`) — never a silent null client. Opening a session on a `models.json` custom model that omits `contextWindow` logs an actionable warning: the runtime otherwise assumes 128k tokens while a small serving runtime (Ollama's default `num_ctx` of 4096) silently truncates the prompt from the front, dropping the system prompt, goal, and tools mid-run (see `docs/model-configuration.md`). `yantra doctor --agent-smoke [provider/model]` opens a live session with a `status` tool, streams normalized events, prints the pinned-environment enumeration, and exits 0/3/130.

## Scheduling & Automation

**Scheduling & Saved-Workflow Runner** _(updated: 2026-07-05 by implement)_
Source spec: [feature_scheduling_runner.md](.spec-lite/features/feature_scheduling_runner.md)
`yantra schedule <workflow> --cron "<expr>"` registers a saved workflow to run unattended on a cron schedule (`--params`/`--params-file`, `--notify {desktop|file|none}`, `--on-confirm pause-and-notify`). Registration validates the workflow exists + lints clean, the cron parses (`croner`, DST-correct), and the params carry no credential-shaped literals. `yantra schedules [--json]` lists schedules with recomputed next fires and flags parked runs; `yantra unschedule <id>` removes one. A lightweight local daemon — `yantra daemon {start|stop|status}` (`start` detaches by default, `--foreground` to stay; single-instance via a `proper-lockfile` lock) — polls the registry every 60s (so CLI edits apply without a restart), fires due schedules through the **same inline executor** an interactive `yantra run` uses (ethics gate, keychain, stores, Brief artifacts, history recording), and notifies. Missed fires (daemon was down) are skipped as `missed`, never caught up in a burst; a schedule never overlaps itself. **Safety rule (four enforcement layers):** a scheduled run reaching a `requires_confirmation` step **pauses-and-notifies — it never executes the step**; `--on-confirm` accepts only `pause-and-notify` (a SQLite `CHECK` + parse-time rejection + a park-only daemon gateway + a chaos property enforce this). A parked run stays resumable with its request pending; `yantra confirm <run-id> grant|deny` resolves it, and the daemon resumes a granted run on its next poll, replaying the human's grant exactly once. Notifications (`completed`/`failed`/`confirmation_needed`) are always recorded to `notifications.jsonl` and, for `desktop`, delivered best-effort via OS-native toast (PowerShell/`osascript`/`notify-send`) degrading to the file record; bodies are secret-free by construction (workflow name + status + paths only). `yantra audit <run-id>` narrates the fire (schedule id, cron, pause-and-notify) from a secret-free `schedule.json` sidecar. Schedules live in the `schedules` table of the local `index.db` (migration v2); all scheduled replay is zero-LLM.

## Personalization & History

**Local Domain Ranking** _(updated: 2026-07-19 by implement)_
Source spec: [feature_domain_ranking.md](.spec-lite/features/feature_domain_ranking.md)
Yantra records a local `+1` whenever a domain appears in deterministic or agentic web search results and a `-1` when that domain is blocked, fails to fetch, or yields unreadable content; scores stay bounded from `-100` to `100` and do not yet influence search or synthesis. Users can inspect the ordered list with `yantra sites list [--json]`, seed or promote a hostname with `yantra sites add <domain>`, and delete one with `yantra sites remove <domain>`. The local index stores normalized domains and aggregate counts only—never full URLs, queries, or page content—and ranking failures never fail the owning run or tool call.

**Persistent Personal Profiles & History** _(updated: 2026-07-03 by implement)_
Source spec: [feature_profiles_and_history.md](.spec-lite/features/feature_profiles_and_history.md)
Yantra keeps a local, rebuildable **SQLite index** at `~/.local/share/yantra/index.db` (via Node's built-in `node:sqlite`, loaded through a `createRequire` shim; the spec's `better-sqlite3` was swapped for it per user choice to avoid native prebuilds). The index holds six tables — `history`, `preferences`, `rate_limits`, `schedules`, `domain_ranks`, and `meta` — behind repository stores, is opened WAL + `foreign_keys` with 0600 perms, and is a **cache not a source of truth**: `rebuildFromRuns()` reconstructs history from `runs/<id>/manifest.json`, and `yantra doctor` (new `indexdb.writable` check) moves a corrupt file aside and auto-rebuilds. Every completed `ask`/`run` is recorded on completion; `yantra list` merges the index with the file-based run store (deduped, file-scan fallback when the index is gone), and the new `yantra usage [--type --since]` rolls up task count + cost by day/provider. Durable defaults live in a human-editable, Zod-validated `~/.config/yantra/profile.yaml` (created by `yantra init`) and are applied as flag defaults for `ask` (explicit flag > `prefs set` > profile.yaml > learned > hardcoded); `yantra profile` shows the merged effective view with provenance, and `yantra prefs get|set|list|approve|--forget` manages the machine layer with real deletion. **Privacy chokepoint:** `buildPersonalizationContext` takes preferences only (never history), emits ≤400 chars from approved rows through the single `sanitize()` chokepoint with a `Sanitized<string>` brand, and is the only thing an LLM sees — enforced three ways (input typing, a 500-run property test, and an `index-db`-on-LLM-path import-graph guard in `pnpm security:static-check`). Cross-run rate-limit persistence folds in the deferred TODO item: the ethics gate's per-host token buckets now load/flush through the `rate_limits` table so budgets survive process restarts (absent store = MVP in-process behavior).

## Research

**Deep-Research Mode (`yantra research`)** _(updated: 2026-07-03 by implement)_
Source spec: [feature_deep_research.md](.spec-lite/features/feature_deep_research.md)
`yantra research "<topic>"` runs a **bounded multi-hop** loop (`packages/core/src/research/`) where `ask` runs one: `search → fetch → extract → pool → interim synthesis for gap analysis → generate follow-up queries → repeat`, then one final long-form synthesis over the whole corpus. Hop 1 maps the topic; later hops target the coverage gaps the synthesis surfaced. Everything is budgeted by a single `BudgetTracker` (injectable clock, no real sleeps) across four dimensions — hops (`--depth {1|2|3}`, default 2), sources (`--max-sources`, default 24), wall-clock (`--budget-ms`, default 180s), and LLM calls (`--budget`, default 12) — and the loop terminates cleanly (`coverage_met` → `max_hops` → budget dimension → `no_novel_queries`), emitting an honest partial Brief with a `budget_exhausted` notice rather than hanging or truncating silently. A `SourcePool` dedups exact (tracking-param/fragment/trailing-slash-normalized URL) and near-duplicate (shared FEAT-014 TF-IDF cosine ≥ 0.85) articles and caps sources per host (default 3, rank-preferential) so one domain can't dominate. A `CoverageTracker` seeds subtopics from the interim synthesis (section headings + recurring named entities), marks each covered once ≥2 pooled docs evidence it, and exposes a heuristic `metadata.coverage` score plus the uncovered gaps. Follow-up queries come from `FollowUpQueryGenerator`: deterministic template expansion over uncovered subtopics (novelty-filtered, capped at 3/hop) or, when a model is wired, an LLM path whose interim overview flows through the single `sanitize()` chokepoint before send and whose output is validated (plain-string/length/charset bounds) with deterministic fallback on any failure — so `--no-llm` (or `LLM_PROVIDER=none`) works end to end. Per-source failures isolate to notices (shared `processSource`, now also used by `AskPipeline`); a search-provider error mid-hop degrades that query to zero results and continues. Output flags mirror `ask` (`--detail`, `--format`, `--length`, `--open`, `--search-provider`, `--json`); each hop also writes a `research-state.json` snapshot (queries, kept/fetched counts, coverage, remaining budget) and a `research_hop_completed` event for post-mortems. Exit codes: 0 ok, 1 validation (e.g. `--depth 4`), 2 execution failure.

## Synthesis

**wink-nlp Local-Analysis Quick Wins** _(updated: 2026-07-19 by implement)_
Source spec: [feature_wink_nlp_quick_wins.md](.spec-lite/features/feature_wink_nlp_quick_wins.md)
The deterministic (`--no-llm`) evidence pipeline now uses three additional local wink-nlp signals, all behind the `TextAnalyzer` port (baseline analyzer stays neutral/byte-stable). **Negation guard**: a claim never merges with its own negation ("sales rose" vs "sales did not rise") — the polarity check applies to near-duplicate merging, sentence-level citation support, and topic-group duplicate absorption, so a contradiction stays visible with its own citations (it renders as a child finding under the claim it disputes). **Opinion demotion**: strongly opinionated fact/number claims (|sentiment| > 0.6) are excluded from the `Key facts` section and land in `Additional findings` instead — demoted, never dropped, and still eligible as key findings; sentiment is never displayed. **Junk gate**: sentences whose surface junk score (Title-Case density, stopword deficit, long words) exceeds 0.5 are rejected at eligibility, catching SEO/nav link glue that carries a finite verb and clean punctuation and so passed every earlier gate; rejected sentences still count in `metadata.evidence.candidate_claims`. Thresholds are corpus-tuned: 0.6 keeps sports prose ("one win from the semi-final" scores 0.8 via "win") in `Key facts`, and 0.5 keeps brand-dense prose ("150 extra trains for FIFA World Cup supporters") from being junked. Golden corpora gained three targeted fixtures (`negation-pair`, `opinion-demote`, `junk-gate`); the seven pre-existing corpora are byte-unchanged.

**Brief Section Consolidation** _(updated: 2026-07-18 by implement)_
Source spec: [feature_brief_section_consolidation.md](.spec-lite/features/feature_brief_section_consolidation.md)
Deterministic (`--no-llm`) Briefs group their detail sections into two honest tiers below Key Findings instead of one section per claim kind: **Key facts** (facts + numbers, with the key-figures table rendered inside it when at least three number claims reduce cleanly, followed by bullets for the remaining facts and numbers) and **Additional findings** (entities, quotes, and any future kinds). The retired `Numbers & figures`, `People & organizations`, and `Notable quotes` headings — the last two degraded to noise because the local NER has no PERSON/ORG types — are gone. Every prior threshold carries over: a section still needs ≥2 groups or it disappears, and detail caps are unchanged. This is a presentation-layer change only; claim selection, findings, overview, facets, and notices are untouched, and the golden-Brief suite was regenerated once.

**Extraction-Grounded Brief Quality** _(updated: 2026-07-12 by implement)_
Source spec: [feature_brief_quality.md](.spec-lite/features/feature_brief_quality.md)
Offline Briefs preserve HTML block boundaries, remove source footnotes and page chrome, reject malformed or junk sentences, and merge contained restatements with their citations. Findings are selected for relevance and diversity; overviews prefer a definitional lead plus central distinct claims, and titles adopt source-backed casing such as `FIFA`. Detail sections are capped and thin sections disappear; the `Key facts` section uses a compact key-figures table when at least three claims reduce cleanly. Citation problems and duplicate notices are aggregated while deterministic output retains the zero-flag invariant.

**Synthesis Engine (deterministic + LLM)** _(updated: 2026-07-11 by implement)_
Source spec: [feature_evidence_first_synthesis.md](.spec-lite/features/feature_evidence_first_synthesis.md)
FEAT-FP-002 update: deterministic synthesis is now block-aware and coherence-focused. The default analyzer wraps winkNLP in `BlockSegmentingAnalyzer`; eligibility collapses claim text, rejects boilerplate, and stitches one-level anaphora; near-duplicate merging also uses shared percent/money anchors; percent facets add a `Metric` column for labels such as `Sales decline (YoY)`, `Sales rise (MoM)`, and `Market share`; and composition groups related claims into parent findings with child bullets plus nested section overflow. The checked-in golden suite now covers six corpora, including `ev-sales-messy`.
Turns N extracted articles into **one** synthesized `Brief` behind a single `Synthesizer` strategy interface (`packages/core/src/synthesis/`). ## Plan Executor

### Plan Executor & Step Verbs (FEAT-005)

The `Executor` class drives a `Plan.steps` array to completion, maintaining an `ExecutionContext` that carries all mutable state for one run: captures, retry budgets, an event bus, a checkpoint store, and an ethics gate. Each step is dispatched through a `STEP_DISPATCH` map (navigate, click, fill, extract, wait_for, assert, branch, loop, call_workflow, llm_summarize). Step results are a discriminated union — `completed`, `retried`, `failed`, `handoff_requested`, `ethics_refused`, or `jump` (for branch goto semantics). The executor enforces a `MAX_TOTAL_STEP_EXECUTIONS` guard to prevent infinite loops.

**Retry budgets** are three independent token counters (`locatorAttempts`, `stepAttempts`, `workflowAttempts`). `consume()` throws `BudgetExhaustedError` past zero. `snapshot()/clone()` support checkpoint-based resume. **Captures** (`InMemoryCaptureStore`) accumulate `extract` step output under `step_id` keys; values >64 KB are represented as sidecar references in snapshots. **Scope enforcement** (`checkScopeViolations`) preflights the entire plan before execution using `ALLOWED_VERBS_BY_SCOPE` from protocol; scope violations abort before step 1 runs.

**Checkpointing** (`FilesystemCheckpointStore`) writes atomically via `.tmp` + `fs.rename` after each successful step. Resume (`resumeFrom`) restores capture state from the snapshot and re-enters the step loop from the checkpoint's `after_step_idx + 1`. **Events** (`JsonlEventBus`) buffer in memory and flush to `events.jsonl` every 200 ms (debounced), with a synchronous `flush()` forced before checkpoint writes. **Reports** (`writeReport`) produce a Markdown call-log at `report.md`.

**Ethics gate** (`EthicsGateImpl`) enforces blocklist first (synchronous) and rate-limiter last (in-process per-host token bucket, injectable `Clock` for tests). Robots.txt enforcement is now opt-in via config (`ethics.robots_enabled: true`); when enabled it runs between blocklist and rate-limiter with 24h per-host caching (fail-open for 404 per RFC 9309, fail-closed for timeouts/5xx). `handleNavigate` calls the gate before any `page.goto`. **Value resolution** (`ValueResolver`) handles `literal`, `param`, `capture`, and `template` refs; secrets use a separate `resolveSecret()` path that returns a `{plaintext, zero}` pair — secrets are never returned by `resolve()` and never appear in step_completed event payloads.

The `FileUsageWriter` batches `UsageCall` records and persists them as a `UsageLedger` at `usage.json`. Stub handlers for `call_workflow` (FEAT-010) and `llm_summarize` (FEAT-011) return structured failures pointing to those features.

## Browser Engine

### Locator Engine & Auto-Wait (FEAT-004)

The locator engine resolves named UI targets via ordered **candidate chains** (each candidate is a typed `LocatorIntent`). `LocatorResolverImpl.resolve(chain)` walks candidates in order, calling the browser-side InjectedScript via `InjectedScriptHost.call()`. Strict mode (default) treats >1 match as an immediate ambiguity failure; per-candidate timeouts fall through to the next candidate rather than aborting. A `LocatorResolutionEvent` is emitted via the optional `LocatorEventSink` after every resolve call carrying chain name, outcome, winning index, and duration (no DOM content — security invariant enforced by property test).

`resolveActionable(chain, host, options)` wraps the resolver in a Playwright-style auto-wait loop: backoff `[0, 20, 50, 100, 100, 500, 500, …]` ms, comparing two `getBoundingRect` snapshots 100 ms apart for stability. Non-retriable failures (`ambiguous`, `frame_detached`) throw immediately; `not_actionable` at deadline throws `LocatorNotActionableError` carrying the last `ActionableState`.

The **InjectedScript bundle** (`dist/injected.bundle.js`, IIFE, < 50 KB, no `require()`, no `process.env`) is built by esbuild from `src/locator/injected/index.ts` and registers `window.__yantra`. Eight resolution strategies are implemented in the injected layer: `role+name` (WAI-ARIA computed role + accessible-name algorithm, ported from Playwright Apache-2.0), `testid` (configurable attribute aliases), `label` (`<label for>`, implicit wrap, aria-labelledby, aria-label), `placeholder`, `text` (normalized + regex), `css` (with a unique-CSS generator using stable-class heuristics), `xpath`, and `relative` (all 7 RelativeRelation variants). `CSS.escape` and `elementFromPoint` are used browser-side.

The **candidate ranking algorithm** (`ranking.ts`, browser-side) scores candidates by base weight (testid=1.00, role=0.90, label=0.75, placeholder=0.60, css=0.45, relative=0.30, xpath=0.10) × specificity × stability, sorts descending, and caps to `topN` (default 5). Ties break by kind order for determinism. Used at record time by FEAT-008.

The `intent-codec.ts` module provides `encodeIntent`/`decodeIntent` for the JSON ↔ `LocatorIntent` round-trip (RegExp serialized as `{ __isRegExp, pattern, flags }`). Errors (`LocatorNotFoundError`, `LocatorAmbiguousError`, `HitTargetInterceptedError`, `LocatorNotActionableError`, `FrameDetachedError`, `LocatorInvalidSelectorError`) all carry structured context for failure reports.

### Chrome Launcher & BrowserProvider (FEAT-003)

`LocalBrowserProvider.launch()` spawns system Chrome over CDP pipe transport (`--remote-debugging-pipe`, no WebSocket port), returning a `LocalBrowserSession`. It validates `LaunchOptions` via Zod, resolves the profile via `LocalProfileStore`, discovers Chrome with `detectChrome()`, and rejects unsupported versions (< 120). Crash events are detected via child-process `exit`, emitted as `BrowserCrashedError`, and ephemeral profiles are cleaned up best-effort. The session's `newPage()` rejects if the session is closed or crashed.

`detectChrome()` discovers Chrome per-platform without ever opening a browser window. On macOS/Linux it reads the version by running `<chrome> --version`. On Windows it deliberately does **not** execute `chrome.exe` (which on Windows prints nothing and instead opens a visible browser window); instead it locates the binary via the App Paths registry key or standard install paths and reads the version from the versioned `Application\<version>` subfolder, falling back to PowerShell `VersionInfo.ProductVersion`. The `reg query` probe discards child stderr so a missing registry key does not leak an error to the console. _(updated: 2026-05-19 by fix)_

`LocalProfileStore` manages per-workflow profile dirs (`~/.local/share/yantra/profiles/<name>` with chmod 0700 on Unix), ephemeral dirs (`<tmpdir>/yantra-<uuid>`), and explicit absolute paths. It enforces a refused-path guard that rejects the user's real Chrome profile roots (macOS Library, Linux .config, Windows AppData).

`yantra doctor` runs seven checks (chrome.detected, chrome.version_min, datadir.writable, datadir.permissions, cachedir.writable, keychain.reachable, indexdb.writable), never throws, caches results for 1 hour at `~/.cache/yantra/doctor.json` (mode 0600), and returns a `DoctorReport` with an `overall` rollup of ok/warn/error. The `indexdb.writable` check opens the SQLite index (auto-rebuilding from the run tree if it was corrupt → warn) and probes a write. Permission checks walk per-workflow profile subdirs and report offenders in `details.offenders`.

Path helpers in `paths.ts` honor `XDG_DATA_HOME`/`XDG_CACHE_HOME` on Linux and `%LOCALAPPDATA%` on Windows.

## Recorder

### Recorder Phase 1 (FEAT-008)

FEAT-008 is implemented across `packages/protocol/src/schemas/recording-draft.ts` and `packages/core/src/workflow/recorder/`. A `RecordingSession` orchestrates a visible Chrome browser session (via puppeteer-core), injects a CDP overlay script into every page, and produces a `draft.json` artifact containing all captured user actions.

The **protocol schema** (`RecordingDraftSchema`, `CapturedActionSchema`) lives in `@yantra/protocol` and enforces the redaction guarantee at the type level: `fill.raw_value` is `z.literal('<redacted>')`, so any attempt to persist an unredacted fill value is a compile-time error. The pre-redaction types (`RawCapturedActionInput`, `RawFillAction`) are internal to the `redactor.ts` module and not re-exported from the recorder barrel.

The **overlay** (esbuild IIFE bundle, built with `pnpm --filter @yantra/core build:recorder-overlay`) runs in-page and captures `click`, `input` (250 ms debounce), `change`, and `keydown(Enter)` events. For each captured action it calls `buildElementDescriptor()` (ARIA role + accessible name + sanitized attr sample + XPath debug string) and forwards the payload to Node via a CDP `Runtime.addBinding` channel. The overlay also draws a fixed-position recording indicator (red dot + action counter) and advises the user to "stop with Ctrl+C in the terminal".

The **redactor** (`DefaultCaptureRedactor`) is the only code that reads `raw_value`; it replaces it with the sentinel `'<redacted>'` and records `value_length` (code-point count). Defense-in-depth `defangAttrValue()` strips credential-shaped strings (sk-, sk-proj-, ghp*, AKIA, eyJ, xoxb-, gho*, glpat-) from element attribute samples before they are persisted.

**Session lifecycle**: `RecordingSession.start(name)` generates a time-ordered recording ID, calls `RecordingStore.create()`, launches Chrome headful, registers the CDP binding and overlay, sets up popup attachment (`PopupHandler`), cross-origin iframe detection, and starts the `IdleWatcher` (default 5-minute timeout, fires `IdleTimeoutPromptEvent`). `RecordingSession.stop(reason)` assembles and Zod-validates the draft via `assembleDraft()`, writes it atomically to `draft.json`, removes the partial draft, closes the browser, and destroys the ephemeral profile unless `keepProfile` was set. `abort()` preserves the profile for post-mortem.

**Crash safety**: `appendAction` + `FileSystemRecordingStore` write `draft.partial.json` atomically (`.tmp` + `fs.rename`) after every captured action. If the process crashes before `stop()`, the partial draft survives on disk.

**Tests** (all tagged `@no-llm`): 66 unit tests across `redactor.spec.ts` (incl. 500-run fast-check property test), `descriptor-builder.spec.ts` (jsdom, 22 tests), `draft-builder.spec.ts` (10 tests), `store.spec.ts` (8 tests), `idle-watcher.spec.ts` (7 fake-timer tests), `session.spec.ts` (4 integration + state-machine tests).

## Security Envelope

### Security Envelope (FEAT-006)

FEAT-006 is implemented across `packages/core/src/sanitizer`, `packages/core/src/secrets`, `packages/core/src/audit`, and `scripts/ci-static-check.ts`.
