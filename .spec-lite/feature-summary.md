## Scheduling & Automation

**Scheduling & Saved-Workflow Runner** _(updated: 2026-07-05 by implement)_
Source spec: [feature_scheduling_runner.md](.spec-lite/features/feature_scheduling_runner.md)
`yantra schedule <workflow> --cron "<expr>"` registers a saved workflow to run unattended on a cron schedule (`--params`/`--params-file`, `--notify {desktop|file|none}`, `--on-confirm pause-and-notify`). Registration validates the workflow exists + lints clean, the cron parses (`croner`, DST-correct), and the params carry no credential-shaped literals. `yantra schedules [--json]` lists schedules with recomputed next fires and flags parked runs; `yantra unschedule <id>` removes one. A lightweight local daemon — `yantra daemon {start|stop|status}` (`start` detaches by default, `--foreground` to stay; single-instance via a `proper-lockfile` lock) — polls the registry every 60s (so CLI edits apply without a restart), fires due schedules through the **same inline executor** an interactive `yantra run` uses (ethics gate, keychain, stores, Brief artifacts, history recording), and notifies. Missed fires (daemon was down) are skipped as `missed`, never caught up in a burst; a schedule never overlaps itself. **Safety rule (four enforcement layers):** a scheduled run reaching a `requires_confirmation` step **pauses-and-notifies — it never executes the step**; `--on-confirm` accepts only `pause-and-notify` (a SQLite `CHECK` + parse-time rejection + a park-only daemon gateway + a chaos property enforce this). A parked run stays resumable with its request pending; `yantra confirm <run-id> grant|deny` resolves it, and the daemon resumes a granted run on its next poll, replaying the human's grant exactly once. Notifications (`completed`/`failed`/`confirmation_needed`) are always recorded to `notifications.jsonl` and, for `desktop`, delivered best-effort via OS-native toast (PowerShell/`osascript`/`notify-send`) degrading to the file record; bodies are secret-free by construction (workflow name + status + paths only). `yantra audit <run-id>` narrates the fire (schedule id, cron, pause-and-notify) from a secret-free `schedule.json` sidecar. Schedules live in the `schedules` table of the local `index.db` (migration v2); all scheduled replay is zero-LLM.

## Discovery Mode

**Discovery Mode (`yantra do` / `discover`)** _(updated: 2026-07-04 by implement)_
Source spec: [feature_discovery_mode.md](.spec-lite/features/feature_discovery_mode.md)
`yantra do "<goal>"` runs a bounded ReAct loop with no saved workflow: propose → validate → confirm-if-needed → execute → observe → repeat, under hard budgets (`--max-steps` default 15, `--budget` LLM calls default 20, `--budget-ms` wall-clock default 5 min). The agent (`packages/agent/src/discovery/propose.ts`) proposes 1-3 standard protocol steps per turn using **semantic locators only** (`intent` role + name_match — `css`/`xpath`/`recorded`/`workflow` kinds are rejected at validation); every mutating step (navigate/click/fill) is force-flagged `requires_confirmation: true` by a normalizing transform regardless of what the model set, so a terminal consent card and y/n prompt (`InteractiveConfirmationGateway`) always gates it — nothing is ever auto-granted (`--yes-to nothing` is the only accepted value). The agent has no access to secrets (`SecretRef` is rejected anywhere in a proposal) and never sees raw page HTML: each cycle's observation (`packages/core/src/discovery/observe.ts`) is a sanitized Readability digest (≤8000 chars, `sanitize()`-cleaned) plus a capped, ranked list of up to 30 interactable elements (role/name/kind/disabled only — no values, no attributes). A hard per-session host allowlist blocks navigation to unlisted hosts (bootstraps from the first proposed host when empty). The session terminates in `goal_met`, `goal_unreachable` (an honest `done` claim), `budget_exhausted`, `user_declined` (a denied confirmation, exit 4), or `aborted` (proposer re-prompt exhaustion / LLM unavailable, exit 2); on `goal_met` it assembles a Brief (visited pages as numbered sources, the model's summary run through the citation-faithfulness validator) and, with `--save-as <name>`, promotes the successful trace into a saved, lint-clean `WorkflowFile` (dead-end cycles dropped, semantic locators named into `_locators`, confirmation annotations preserved).
**Current limitation**: no code path anywhere in the repo (not introduced by this feature) wires a real element-locator host to a live browser page, so `click`/`fill`/`extract`/`wait_for`/`assert` do not yet execute against a real site — `navigate`-only goals work today. This also affects `yantra run`. Tracked in `.spec-lite/TODO.md`.

## Personalization & History

**Persistent Personal Profiles & History** _(updated: 2026-07-03 by implement)_
Source spec: [feature_profiles_and_history.md](.spec-lite/features/feature_profiles_and_history.md)
Yantra keeps a local, rebuildable **SQLite index** at `~/.local/share/yantra/index.db` (via Node's built-in `node:sqlite`, loaded through a `createRequire` shim; the spec's `better-sqlite3` was swapped for it per user choice to avoid native prebuilds). The index holds four tables — `history`, `preferences`, `rate_limits`, `meta` — behind repository stores (`HistoryStore`/`PreferenceStore`/`RateLimitStore`), is opened WAL + `foreign_keys` with 0600 perms, and is a **cache not a source of truth**: `rebuildFromRuns()` reconstructs history from `runs/<id>/manifest.json`, and `yantra doctor` (new `indexdb.writable` check) moves a corrupt file aside and auto-rebuilds. Every completed `ask`/`run` is recorded on completion; `yantra list` merges the index with the file-based run store (deduped, file-scan fallback when the index is gone), and the new `yantra usage [--type --since]` rolls up task count + cost by day/provider. Durable defaults live in a human-editable, Zod-validated `~/.config/yantra/profile.yaml` (created by `yantra init`) and are applied as flag defaults for `ask` (explicit flag > `prefs set` > profile.yaml > learned > hardcoded); `yantra profile` shows the merged effective view with provenance, and `yantra prefs get|set|list|approve|--forget` manages the machine layer with real deletion. **Privacy chokepoint:** `buildPersonalizationContext` takes preferences only (never history), emits ≤400 chars from approved rows through the single `sanitize()` chokepoint with a `Sanitized<string>` brand, and is the only thing an LLM sees — enforced three ways (input typing, a 500-run property test, and an `index-db`-on-LLM-path import-graph guard in `pnpm security:static-check`). Cross-run rate-limit persistence folds in the deferred TODO item: the ethics gate's per-host token buckets now load/flush through the `rate_limits` table so budgets survive process restarts (absent store = MVP in-process behavior).

## Research

**Deep-Research Mode (`yantra research`)** _(updated: 2026-07-03 by implement)_
Source spec: [feature_deep_research.md](.spec-lite/features/feature_deep_research.md)
`yantra research "<topic>"` runs a **bounded multi-hop** loop (`packages/core/src/research/`) where `ask` runs one: `search → fetch → extract → pool → interim synthesis for gap analysis → generate follow-up queries → repeat`, then one final long-form synthesis over the whole corpus. Hop 1 maps the topic; later hops target the coverage gaps the synthesis surfaced. Everything is budgeted by a single `BudgetTracker` (injectable clock, no real sleeps) across four dimensions — hops (`--depth {1|2|3}`, default 2), sources (`--max-sources`, default 24), wall-clock (`--budget-ms`, default 180s), and LLM calls (`--budget`, default 12) — and the loop terminates cleanly (`coverage_met` → `max_hops` → budget dimension → `no_novel_queries`), emitting an honest partial Brief with a `budget_exhausted` notice rather than hanging or truncating silently. A `SourcePool` dedups exact (tracking-param/fragment/trailing-slash-normalized URL) and near-duplicate (shared FEAT-014 TF-IDF cosine ≥ 0.85) articles and caps sources per host (default 3, rank-preferential) so one domain can't dominate. A `CoverageTracker` seeds subtopics from the interim synthesis (section headings + recurring named entities), marks each covered once ≥2 pooled docs evidence it, and exposes a heuristic `metadata.coverage` score plus the uncovered gaps. Follow-up queries come from `FollowUpQueryGenerator`: deterministic template expansion over uncovered subtopics (novelty-filtered, capped at 3/hop) or, when a model is wired, an LLM path whose interim overview flows through the single `sanitize()` chokepoint before send and whose output is validated (plain-string/length/charset bounds) with deterministic fallback on any failure — so `--no-llm` (or `LLM_PROVIDER=none`) works end to end. Per-source failures isolate to notices (shared `processSource`, now also used by `AskPipeline`); a search-provider error mid-hop degrades that query to zero results and continues. Output flags mirror `ask` (`--detail`, `--format`, `--length`, `--open`, `--search-provider`, `--json`); each hop also writes a `research-state.json` snapshot (queries, kept/fetched counts, coverage, remaining budget) and a `research_hop_completed` event for post-mortems. Exit codes: 0 ok, 1 validation (e.g. `--depth 4`), 2 execution failure.

## Synthesis

**Extraction-Grounded Brief Quality** _(updated: 2026-07-12 by implement)_
Source spec: [feature_brief_quality.md](.spec-lite/features/feature_brief_quality.md)
Offline Briefs preserve HTML block boundaries, remove source footnotes and page chrome, reject malformed or junk sentences, and merge contained restatements with their citations. Findings are selected for relevance and diversity; overviews prefer a definitional lead plus central distinct claims, and titles adopt source-backed casing such as `FIFA`. Detail sections are capped and thin sections disappear; `Numbers & figures` uses a compact key-figures table when at least three claims reduce cleanly. Citation problems and duplicate notices are aggregated while deterministic output retains the zero-flag invariant.

**Synthesis Engine (deterministic + LLM)** _(updated: 2026-07-11 by implement)_
Source spec: [feature_evidence_first_synthesis.md](.spec-lite/features/feature_evidence_first_synthesis.md)
FEAT-FP-002 update: deterministic synthesis is now block-aware and coherence-focused. The default analyzer wraps winkNLP in `BlockSegmentingAnalyzer`; eligibility collapses claim text, rejects boilerplate, and stitches one-level anaphora; near-duplicate merging also uses shared percent/money anchors; percent facets add a `Metric` column for labels such as `Sales decline (YoY)`, `Sales rise (MoM)`, and `Market share`; and composition groups related claims into parent findings with child bullets plus nested section overflow. The checked-in golden suite now covers six corpora, including `ev-sales-messy`.
Turns N extracted articles into **one** synthesized `Brief` behind a single `Synthesizer` strategy interface (`packages/core/src/synthesis/`). The `DeterministicSynthesizer` (the `--no-llm` contract and golden-test backbone) is now **evidence-first**: it selects evidence before it assembles a document. A local, deterministic winkNLP analyzer (`wink-nlp` + `wink-eng-lite-web-model`, behind a `TextAnalyzer` port) drives every stage in `synthesis/evidence/`: `buildQueryProfile` infers intent (price/comparison/rate-or-trend/factual/entity/general) with required evidence kinds and buildable facet columns; a **source relevance gate** drops off-topic sources (a NASA Mars page in an "EV sales" set) before clustering/numbering, recording each as a `source_excluded` notice; **eligibility gates** reject headings (no finite verb), wrong-kind figures, and off-topic sentences; **sentence-level citation support** replaces whole-doc token overlap so a claim is cited only by docs whose sentences actually restate it (no more `[1][4][6][7][8]` runs); an **entity-anchored facet planner** builds only query-relevant, anchored comparison columns; and the `EvidenceSet` treats length budgets (short=3/medium=6/long=10) as **caps, never fill targets**, near-dup-merges paraphrases, and emits a `limited_evidence` notice when fewer relevant findings survive than requested. Key findings carry citations only in the structured `citations[]` array; overview/sections keep inline `[n]`. `metadata.evidence` reports candidate/accepted claim counts and excluded-source counts; `coverage` is over included sources. `LlmSynthesizer` (default for `public` scope) is unchanged: sanitize → send → validate → re-prompt ≤2 → deterministic fallback (`metadata.deterministic_fallback_used`). The post-synthesis citation-faithfulness validator still enforces no-uncited-claims (verdict in `metadata.citation_verdict`); the `synthesis_completed` event is still emitted. A checked-in golden-Brief suite (`e2e/golden-briefs/`, regenerate with `pnpm golden:update`) byte-pins the deterministic output for five corpora, including `ev-sales-mixed` which pins the off-topic-exclusion behavior.

## Plan Executor

### Plan Executor & Step Verbs (FEAT-005)

The `Executor` class drives a `Plan.steps` array to completion, maintaining an `ExecutionContext` that carries all mutable state for one run: captures, retry budgets, an event bus, a checkpoint store, and an ethics gate. Each step is dispatched through a `STEP_DISPATCH` map (navigate, click, fill, extract, wait_for, assert, branch, loop, call_workflow, llm_summarize). Step results are a discriminated union — `completed`, `retried`, `failed`, `handoff_requested`, `ethics_refused`, or `jump` (for branch goto semantics). The executor enforces a `MAX_TOTAL_STEP_EXECUTIONS` guard to prevent infinite loops.

**Retry budgets** are three independent token counters (`locatorAttempts`, `stepAttempts`, `workflowAttempts`). `consume()` throws `BudgetExhaustedError` past zero. `snapshot()/clone()` support checkpoint-based resume. **Captures** (`InMemoryCaptureStore`) accumulate `extract` step output under `step_id` keys; values >64 KB are represented as sidecar references in snapshots. **Scope enforcement** (`checkScopeViolations`) preflights the entire plan before execution using `ALLOWED_VERBS_BY_SCOPE` from protocol; scope violations abort before step 1 runs.

**Checkpointing** (`FilesystemCheckpointStore`) writes atomically via `.tmp` + `fs.rename` after each successful step. Resume (`resumeFrom`) restores capture state from the snapshot and re-enters the step loop from the checkpoint's `after_step_idx + 1`. **Events** (`JsonlEventBus`) buffer in memory and flush to `events.jsonl` every 200 ms (debounced), with a synchronous `flush()` forced before checkpoint writes. **Reports** (`writeReport`) produce a Markdown call-log at `report.md`.

**Ethics gate** (`EthicsGateImpl`) enforces blocklist first (synchronous) and rate-limiter last (in-process per-host token bucket, injectable `Clock` for tests). Robots.txt enforcement is now opt-in via config (`ethics.robots_enabled: true`); when enabled it runs between blocklist and rate-limiter with 24h per-host caching (fail-open for 404 per RFC 9309, fail-closed for timeouts/5xx). `handleNavigate` calls the gate before any `page.goto`. **Value resolution** (`ValueResolver`) handles `literal`, `param`, `capture`, and `template` refs; secrets use a separate `resolveSecret()` path that returns a `{plaintext, zero}` pair — secrets are never returned by `resolve()` and never appear in step_completed event payloads.

The `FileUsageWriter` batches `UsageCall` records and persists them as a `UsageLedger` at `usage.json`. Stub handlers for `call_workflow` (FEAT-010) and `llm_summarize` (FEAT-011) return structured failures pointing to those features.

## Browser Engine

### Locator Engine & Auto-Wait (FEAT-004)

The locator engine resolves named UI targets via ordered **candidate chains** (each candidate is a typed `LocatorIntent`). `LocatorResolverImpl.resolve(chain)` walks candidates in order, calling the browser-side InjectedScript via `InjectedScriptHost.call()`. Strict mode (default) treats >1 match as an immediate ambiguity failure; per-candidate timeouts fall through to the next candidate rather than aborting. A `LocatorResolutionEvent` is emitted via the optional `LocatorEventSink` after every resolve call carrying chain name, outcome, winning index, and duration (no DOM content — security invariant enforced by property test).

`resolveActionable(chain, host, options)` wraps the resolver in a Playwright-style auto-wait loop: backoff `[0, 20, 50, 100, 100, 500, 500, …]` ms, comparing two `getBoundingRect` snapshots 100 ms apart for stability. Non-retriable failures (`ambiguous`, `frame_detached`) throw immediately; `not_actionable` at deadline throws `LocatorNotActionableError` carrying the last `ActionableState`.

The **InjectedScript bundle** (`dist/injected.bundle.js`, IIFE, < 50 KB, no `require()`, no `process.env`) is built by esbuild from `src/locator/injected/index.ts` and registers `window.__yantra`. Eight resolution strategies are implemented in the injected layer: `role+name` (WAI-ARIA computed role + accessible-name algorithm, ported from Playwright Apache-2.0), `testid` (configurable attribute aliases), `label` (`<label for>`, implicit wrap, aria-labelledby, aria-label), `placeholder`, `text` (normalized + regex), `css` (with a unique-CSS generator using stable-class heuristics), `xpath`, and `relative` (all 7 RelativeRelation variants). `CSS.escape` and `elementFromPoint` are used browser-side.

The **candidate ranking algorithm** (`ranking.ts`, browser-side) scores candidates by base weight (testid=1.00, role=0.90, label=0.75, placeholder=0.60, css=0.45, relative=0.30, xpath=0.10) × specificity × stability, sorts descending, and caps to `topN` (default 5). Ties break by kind order for determinism. Used at record time by FEAT-008.

The `intent-codec.ts` module provides `encodeIntent`/`decodeIntent` for the JSON ↔ `LocatorIntent` round-trip (RegExp serialized as `{ __isRegExp, pattern, flags }`). Errors (`LocatorNotFoundError`, `LocatorAmbiguousError`, `HitTargetInterceptedError`, `LocatorNotActionableError`, `FrameDetachedError`, `LocatorInvalidSelectorError`) all carry structured context for failure reports.

### Chrome Launcher & BrowserProvider (FEAT-003)

`LocalBrowserProvider.launch()` spawns system Chrome over CDP pipe transport (`--remote-debugging-pipe`, no WebSocket port), returning a `LocalBrowserSession`. It validates `LaunchOptions` via Zod, resolves the profile via `LocalProfileStore`, discovers Chrome with `detectChrome()`, and rejects unsupported versions (< 120). Crash events are detected via child-process `exit`, emitted as `BrowserCrashedError`, and ephemeral profiles are cleaned up best-effort. The session's `newPage()` rejects if the session is closed or crashed.

`detectChrome()` discovers Chrome per-platform without ever opening a browser window. On macOS/Linux it reads the version by running `<chrome> --version`. On Windows it deliberately does **not** execute `chrome.exe` (which on Windows prints nothing and instead opens a visible browser window); instead it locates the binary via the App Paths registry key or standard install paths and reads the version from the versioned `Application\<version>` subfolder, falling back to PowerShell `VersionInfo.ProductVersion`. The `reg query` probe discards child stderr so a missing registry key does not leak an error to the console. _(updated: 2026-05-19 by fix)_

`LocalProfileStore` manages per-workflow profile dirs (`~/.local/share/yantra/profiles/<name>` with chmod 0700 on Unix), ephemeral dirs (`<tmpdir>/yantra-<uuid>`), and explicit absolute paths. It enforces a refused-path guard that rejects the user's real Chrome profile roots (macOS Library, Linux .config, Windows AppData).

`yantra doctor` runs seven checks (chrome.detected, chrome.version_min, datadir.writable, datadir.permissions, cachedir.writable, keychain.reachable, indexdb.writable), never throws, caches results for 1 hour at `~/.cache/yantra/doctor.json` (mode 0600), and returns a `DoctorReport` with an `overall` rollup of ok/warn/error. The `indexdb.writable` check opens the SQLite index (auto-rebuilding from the run tree if it was corrupt → warn) and probes a write. Permission checks walk per-workflow profile subdirs and report offenders in `details.offenders`.

Path helpers in `paths.ts` honor `XDG_DATA_HOME`/`XDG_CACHE_HOME` on Linux and `%LOCALAPPDATA%` on Windows.

## Rendering

**Rich Document Renderer** _(updated: 2026-07-11 by implement)_
Source spec: [feature_rich_renderer.md](.spec-lite/features/feature_rich_renderer.md)
One `Brief` renders four ways. **Terminal** (`apps/cli/src/render/brief-terminal.ts`, `renderBriefTerminal`): a `boxen` overview panel, `chalk`-styled `[n]` citations and glyph bullets, a width-fitted `cli-table3` comparison table, and a dim numbered source list, with progressive disclosure via `--detail` (`overview` = title+overview+sources; `standard` = +key findings+comparison+notices; `full` = +sections+per-source lines). Color is forced on/off explicitly (never TTY-sniffed) and `--no-color`/`NO_COLOR`/non-TTY produces zero ANSI bytes; width clamps to 60–120. **`brief.md`** (`packages/core/src/brief/to-markdown.ts`): pure, full-detail, GitHub-flavored Markdown; citation runs are capped to `[1][4][7] (+2)` (full evidence stays in `brief.json`). **`brief.html`** (`to-html.ts`): a self-contained, **inert** document — every source-derived string is HTML-escaped at assembly, links are scheme-filtered to http(s) with `rel="noopener noreferrer"`, and there is no `<script>`, remote asset, or `javascript:`/`data:` vector (property-tested with jsdom). Citations render as **small, muted superscripts** capped at 3 visible with a `+k` hover affordance: findings emit their structured `citations[]`, inline `[n]` runs in prose are transformed post-markdown by a tag-aware regex (never touching attribute values), each anchor is an internal `#src-n` fragment resolving to a `id="src-n"` Sources entry, and the whole transform only ever adds `sup`/`a`/`span`. **`--json`** emits the Brief verbatim in a byte-stable envelope and is a parallel, dependency-free path — `render/json.ts` and its import closure may never pull the rendering toolchain (`marked`/`marked-terminal`/`cli-table3`/`chalk`/`boxen`), enforced by `scripts/ci-static-check.ts`. Artifacts are written atomically (`.tmp` + rename) as best-effort; a write failure degrades to a run-level warning, not a run failure.

**Configurable Search Provider Registry** _(updated: 2026-07-03 by implement)_
Source spec: [feature_search_registry.md](.spec-lite/features/feature_search_registry.md)
Search is a registry of first-class providers keyed by name — `google`, `duckduckgo`, `brave`, `tavily` — one descriptor per provider in `search/registry.ts` (the retired `browser` name is gone). `resolveSearchProvider()` picks one by precedence `--search-provider` flag > `SEARCH_PROVIDER` env > `config.search.provider` > `auto`. Selecting a keyed provider whose API key is missing **fails loud** with a `SearchProviderKeyMissingError` (actionable hint), replacing the old silent warn-and-fall-back. `auto` walks the ordered `search.fallback_chain` (default `tavily → brave → duckduckgo`), skipping API providers whose keys are absent; key-free scraped providers always resolve, so a chain ending in `duckduckgo` never fails, and an all-API chain with no keys yields `NoSearchProviderAvailableError`. `tavily`/`brave` are API providers (`tavily.api_key`/`brave.api_key` in the keychain, never in `config.yaml`); `google`/`duckduckgo` scrape via a shared `ScrapeTransport` that launches Chrome with a realistic desktop User-Agent (matching the detected Chrome major, never `HeadlessChrome`) plus `--disable-blink-features=AutomationControlled`, and runs the ethics gate before every SERP fetch. When a scraped engine serves an anomaly/consent/CAPTCHA page, the provider returns a typed `anomaly-challenge` error advising a keyed provider — never evasion. Google is opt-in (not in the default chain — highest anti-bot friction). The `search:` config block is Zod-validated at load (unknown provider name → startup error); `fallback_chain` entries are de-duplicated. A parameterized contract suite exercises every registered descriptor (result shape, rank ordering, limit, abort, key/ethics behavior, typed-error taxonomy), so a new provider is automatically under contract.

Fetching and extraction are handled by `HybridContentFetcher` (`fetcher.ts`) and `ReadabilityExtractor` (`readability.ts`) with resilient malformed-document handling. Summarization defaults to `RuleBasedSummarizer` (`summarizer.ts`) and the LLM seam is in place via `createLlmSummarizer()` (`llm-summarizer.ts`), which intentionally returns `null` under FEAT-007 gates so the feature remains fully usable with `LLM_PROVIDER=none`.

Output rendering is implemented in `card.ts` for terminal, JSON, and markdown report paths. Cache storage is implemented in `cache.ts` and `cache-key.ts` with UTC-day scoping, TTL enforcement, and size-cap eviction.

CLI integration is implemented in `apps/cli/src/commands/ask.ts` and wired through `apps/cli/src/index.ts`/`apps/cli/src/bin.ts`. The command supports `--json`, `--no-llm`, `--no-cache`, `--search-provider`, `--limit`, `--fetch-timeout`, `--budget-ms`, and `--budget`.

Verification coverage includes extraction unit suites under `packages/core/tests/extraction`, CLI ask command tests under `apps/cli/src/commands/ask.spec.ts`, and ask-focused E2E tests in `e2e/ask.spec.ts` and `e2e/ask-no-llm.spec.ts`.

## Recorder

### Recorder Phase 1 (FEAT-008)

FEAT-008 is implemented across `packages/protocol/src/schemas/recording-draft.ts` and `packages/core/src/workflow/recorder/`. A `RecordingSession` orchestrates a visible Chrome browser session (via puppeteer-core), injects a CDP overlay script into every page, and produces a `draft.json` artifact containing all captured user actions.

The **protocol schema** (`RecordingDraftSchema`, `CapturedActionSchema`) lives in `@yantra/protocol` and enforces the redaction guarantee at the type level: `fill.raw_value` is `z.literal('<redacted>')`, so any attempt to persist an unredacted fill value is a compile-time error. The pre-redaction types (`RawCapturedActionInput`, `RawFillAction`) are internal to the `redactor.ts` module and not re-exported from the recorder barrel.

The **overlay** (esbuild IIFE bundle, built with `pnpm --filter @yantra/core build:recorder-overlay`) runs in-page and captures `click`, `input` (250 ms debounce), `change`, and `keydown(Enter)` events. For each captured action it calls `buildElementDescriptor()` (ARIA role + accessible name + sanitized attr sample + XPath debug string) and forwards the payload to Node via a CDP `Runtime.addBinding` channel. The overlay also draws a fixed-position recording indicator (red dot + action counter) and advises the user to "stop with Ctrl+C in the terminal".

The **redactor** (`DefaultCaptureRedactor`) is the only code that reads `raw_value`; it replaces it with the sentinel `'<redacted>'` and records `value_length` (code-point count). Defense-in-depth `defangAttrValue()` strips credential-shaped strings (sk-, sk-proj-, ghp*, AKIA, eyJ, xoxb-, gho*, glpat-) from element attribute samples before they are persisted.

**Session lifecycle**: `RecordingSession.start(name)` generates a time-ordered recording ID, calls `RecordingStore.create()`, launches Chrome headful, registers the CDP binding and overlay, sets up popup attachment (`PopupHandler`), cross-origin iframe detection, and starts the `IdleWatcher` (default 5-minute timeout, fires `IdleTimeoutPromptEvent`). `RecordingSession.stop(reason)` assembles and Zod-validates the draft via `assembleDraft()`, writes it atomically to `draft.json`, removes the partial draft, closes the browser, and destroys the ephemeral profile unless `keepProfile` was set. `abort()` preserves the profile for post-mortem.

**Crash safety**: `appendAction` + `FileSystemRecordingStore` write `draft.partial.json` atomically (`.tmp` + `fs.rename`) after every captured action. If the process crashes before `stop()`, the partial draft survives on disk.

**Tests** (all tagged `@no-llm`): 66 unit tests across `redactor.spec.ts` (incl. 500-run fast-check property test), `descriptor-builder.spec.ts` (jsdom, 22 tests), `draft-builder.spec.ts` (10 tests), `store.spec.ts` (8 tests), `idle-watcher.spec.ts` (7 fake-timer tests), `session.spec.ts` (4 integration + state-machine tests).

## Agent Integration

### Agent Integration — pi-agent-core Adapter (FEAT-011)

`packages/agent` provides the `LLMClient` strategy interface wrapping `pi-agent-core` behind a stable internal boundary. The package cannot import `@yantra/core` (architectural boundary enforced at the compiler level). The `createLLMClient(config)` factory resolves the provider from `LLM_PROVIDER` env → config → degrades gracefully to `NullLLMClient` (returns `LLMUnavailable` immediately, zero I/O) when `LLM_PROVIDER=none` or `pi-agent-core` is unavailable.

`runGeneratePlan()` implements the full generation loop: sanitizer guard → system-prompt assembly (tools sorted by name for canonical SHA-256 hash) → provider call → Zod schema validation → semantic validation (FEAT-002's `validateSemantics`) → bounded re-prompt (max `budget.maxCalls` retries, errors serialized as JSON-pointer paths). On repeated failure `dominantErrorCode()` picks the most-frequent validation error code and `resolveUserFacingHint()` maps it to an actionable message. `wrapWithAudit()` wraps any `LLMClient` to emit two `AgentJsonlEntry` records per call (request + response) with fields including `run_id`, `provider_id`, `system_prompt_hash`, `tool_calls`, token counts, `cost_estimate_usd`, `attempt`, and `outcome`. `estimateCostUsd()` covers Claude 4 and 3.5 model families. `Sanitized<T>` brand type plus LRU-registry `assertSanitized()` enforce runtime sanitization at the LLM call boundary. `InMemoryAuditWriter` and `InMemoryUsageWriter` are provided for testing without I/O.

## CLI Surface

**CLI Polish, Audit, Distribution** _(updated: 2026-05-16 by implement)_
Source spec: [feature_cli_polish_distribution.md](.spec-lite/features/feature_cli_polish_distribution.md)
Caps the MVP with the user-visible command surface: `yantra ask`, `run`, `resume`, `list`, `show`, `lint`, `audit`, `report`, `doctor`, `init` — all behind a single `yantra` binary with a documented exit-code map (0 OK / 1 validation / 2 execution / 3 environment / 4 user-handoff). The `--json` flag emits a stable `schemaVersion` envelope on every command for scripting (currently `"0.2"`, tracking the protocol schema version; `"0.1"` consumers remain compatible — the bump was additive). `yantra audit <run-id>` builds a structured audit report (trust narrative + agent/secret/engine sections) from `manifest.json` + `agent.jsonl` + `secrets.jsonl` + `events.jsonl` without ever surfacing secret values. `yantra report <run-id>` prints (or `--open`s) the per-run `report.md` verbatim. `yantra doctor` extends FEAT-003 v0 with overall ok/warn/fail rollups and remediation hints.

The `ConnectorIO` interface in `apps/cli/src/connector-io.ts` is the load-bearing abstraction that decouples the CLI surface from the underlying executor — Phase 2 connectors (WhatsApp, email, web) plug in by implementing this single interface. `TerminalRenderer` and `JSONRenderer` are interchangeable implementations of `OutputRenderer`; `buildRenderOpts(flags)` picks between them at process start based on `--json` / TTY detection / `NO_COLOR`. The runtime helper (`apps/cli/src/runtime.ts`) wires the workflow orchestrator dependency graph (ethics gate, browser provider, keychain, profile store, workflow store, run store) so individual subcommands don't repeat the boilerplate.

Verification: 29 unit tests across `apps/cli/src/` (commander setup, exit-code map, global-flags parser, ConnectorIO contract, audit-builder round-trip, auto-detect for `show`); 7 e2e tests in `e2e/cli-commands.spec.ts` covering the no-args banner, `list runs|workflows --json` empty roots, `audit`/`report` not-found paths, and `init --provider {none|invalid}`. Distribution channels (npm `bin: { yantra: dist/bin.js }`, Homebrew tap, Scoop bucket) and the bundled-CLI release pipeline are deferred to the first stable release.

## Consent & Safety

**Human-in-the-Loop Action Gateway** _(updated: 2026-07-04 by fix)_
Source spec: [feature_human_in_the_loop.md](.spec-lite/features/feature_human_in_the_loop.md)
Steps flagged `requires_confirmation` (legal on `click`, `fill`, `navigate`) make the executor **pause** before any side-effect machinery, emit a structured `ConfirmationRequest` (action kind, host, description, expected cost, consequence), persist it to `confirmations.jsonl`, and block on an injected `ConfirmationGateway` until a human resolves it. Consent is **unforgeable by type** — the `ConfirmationDecision.decided_by` union has no agent variant (`user_interactive | user_cli_confirm | timeout` only). Deny or timeout terminates the run as a user-handoff abort (exit 4) with a structured `report.md`. Interactive `yantra run` / `yantra resume` (TTY, not `--json`) inject an `InteractiveConfirmationGateway` that renders a consent card with a `[y/N]` prompt defaulting to deny (fail-closed) and proceeds in-process on a grant; `--json` / non-TTY runs wire no gateway, so a flagged step fails closed as a user-handoff abort rather than self-authorizing. `yantra confirm <run-id> {grant|deny}` records a decision for a pending request (the async park → `confirm` → `resume` grant-lookup that lets a resumed run consume a prior grant instead of re-requesting is still in progress — tracked in `.spec-lite/TODO.md`). The annotate flow offers the flag per kept `click` action (defaulting yes for purchase-shaped clicks via a buy/pay/book/order/submit heuristic), and a new `CriticalActionWithoutConfirmation` lint rule warns when a purchase-shaped step lacks the flag. A chaos suite verifies three enforcement layers: 100% consent requirement, no agent pre-satisfaction, and audit completeness in both `confirmations.jsonl` and `events.jsonl`.

## Discovery Mode

**Discovery Mode (`yantra do` / `discover`)** _(updated: 2026-07-04 by implement)_
Source spec: [feature_discovery_mode.md](.spec-lite/features/feature_discovery_mode.md)
FEAT-020 is in progress. **TASK-001 (Discovery sub-protocol schemas) is complete.** `packages/protocol/src/schemas/discovery.ts` defines the bounded ReAct sub-protocol types: `DiscoverySession` (ULID, goal, budget, host allowlist, cycles, terminal outcome, optional promoted workflow), `DiscoveryCycle` (one propose→act→observe turn), `DiscoveryProposal` (untrusted LLM output: rationale + 1–3 standard `Step`s + optional `done` claim), `DiscoveryObservation` (post-sanitizer page state: URL, title, page digest, ≤30 `InteractableDescriptor`s, typed `step_outcome`), `DiscoveryBudget` (hard caps: max_steps, max_llm_calls, max_wall_clock_ms, max_cost_usd), `BudgetSnapshot`, and `DiscoveryValidation`. Security invariants are enforced at the schema level: (1) **semantic-locators-only** — `recorded` and `workflow` locator kinds are rejected in proposals (only `intent` locators allowed); (2) **`SecretRef` rejected** anywhere in proposal step values (including nested in template bindings) — discovery has no secret access; (3) **mutating verbs force confirmation** — `normalizeProposal()` overrides `requires_confirmation: true` on every `navigate`/`click`/`fill` step regardless of what the model set (defense in depth); (4) bounded string lengths on `rationale` (1000) and `summary_md` (4000). `validateDiscoveryProposal()` combines base Zod parsing with the discovery-specific refinements, returning actionable path-tagged rejection reasons. Two additive task events (`discovery_cycle_completed`, `discovery_session_completed`) are added to the `TaskEvent` discriminated union. `discovery-session.json` is registered in `JSON_SCHEMA_ARTIFACTS` for JSON Schema emission. All types are exported from `@yantra/protocol`. **119 unit tests** cover schema acceptance/rejection, the confirmation-forcing transform, secret-ref and non-semantic-locator rejection with path verification, 4-step proposal rejection, and property tests (malformed proposals/sessions/observations never panic the validator). Full protocol suite: 20 files, 222 tests, all green. Remaining tasks: TASK-002 (agent proposer), TASK-003 (observation builder), TASK-004 (`do` driver loop), TASK-005 (workflow promotion), TASK-006 (chaos + property tests).

## Security Envelope

### Security Envelope (FEAT-006)

FEAT-006 is implemented across `packages/core/src/sanitizer`, `packages/core/src/secrets`, `packages/core/src/audit`, and `scripts/ci-static-check.ts`. The sanitizer now has a single chokepoint `sanitize(payload, profile, hostHint?)` with deterministic transform ordering, profile matrix (`public`, `read-only-data`, `authenticated`), host override support, transformation tagging, and UTF-8-safe truncation. The `llm_summarize` handler in the executor sends `sanitized.text`, ensuring LLM-bound content flows through the sanitizer path.

Secret handling is now centralized through the opaque resolver/keychain boundary. `DefaultOpaqueRefResolver` resolves `ValueRef` variants and emits secret-resolution metadata (never secret values), `createKeychainProvider()` returns either a keytar-backed provider or a degraded unavailable provider with one-shot warning logging, and `withSecret` provides best-effort in-memory zeroing semantics for transient secret usage.

Contextual scope enforcement is now a shared core primitive: `packages/core/src/secrets/scope-enforcer.ts` validates plans and rejects mutating behavior in `read-only-data` scope, while the executor wrapper delegates to it and maps violations into executor-level errors.

Audit output is now complete for the FEAT-006 surface. `JsonlAuditLogWriter` appends `agent.jsonl` and `secrets.jsonl` entries, writes scope-summary data into run manifests, and `FilesystemReportBuilder` renders a readable `report.md` from run artifacts. The CI guard `security:static-check` is wired to `scripts/ci-static-check.ts`, which enforces sanitize-before-send and package-boundary restrictions for `pi-agent-core` imports.

Verification coverage includes targeted FEAT-006 suites (12 files / 48 tests) covering sanitizer transforms/profiles/truncation/host overrides, keychain and resolver behavior, scope enforcement, secret zeroing, audit writer/report builder, and static-check fixtures. Property-based tests are in place for sanitizer invariants, query/token stripping, UTF-8 truncation safety, scope validation, and JSONL parseability.
