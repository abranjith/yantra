## Agent Runtime

**Unified Browser Fill Engine** _(updated: 2026-08-12 by fix)_
Source spec: [feature_browser_fill_engine.md](.spec-lite/features/feature_browser_fill_engine.md)
Browser-driven `do` runs now expose two fill tools: `browser_fill_element` for one control and `browser_fill_form` for an ordered non-secret form. Both route text, reactive suggestions, native choices, toggles, and ISO dates/ranges through one deterministic core engine that verifies the committed state, releases floating widgets, and reports stable typed failures; the single-field tool also owns the host-bound secret path, while controller-level identity healing retries a uniquely re-rendered ref once. Successful fills record semantic `fill_element` trace steps, and promoted workflows replay those steps through the same engine with literal, parameter, capture, or secret values instead of brittle calendar click chains. Calendar reading takes a cell's date from its own subtree only — an `aria-hidden` container higher up the page no longer blanks every date, and a cell the page hides that way is treated as unavailable even when it carries no disabled attribute. Committed dates verify after the widget is released rather than before, accept either slashed field order (with or without a year — a compact trigger showing `Sun 9/6` verifies, while `1.5` stays a number because only `/` admits the year-less form), accept a widget that renders no year while still requiring one that does to agree, and read a range spread across a uniquely named check-in/check-out pair whose ends may be `button`s rather than text boxes (the compact shape KAYAK and similar sites use) — with the calendar's own day cells excluded from that pair, since an open picker labels its chosen days "Selected as start date" and driving the range from a day cell opens nothing. A control's committed value is read from every surface it offers — `aria-valuetext`, accessible name, rendered text, de-duplicated — because which surface holds the value and which holds the label differs by site: one picker writes its selection into `aria-label` and keeps "Dates" as its text, another is permanently labelled "Select start date from calendar input" and shows `Sun 9/6`. A `date_range` on a resolvable pair is never failed by the driver from a single control; the engine decides after release. **Opening a widget survives a page with more than one popup on it.** Each open attempt gets its own budget; an undeclared container counts only if the click produced it, so the scan can no longer settle on permanent popup-shaped page chrome; a container that vanishes is read as "our click closed an already-open widget" only after nothing new appears within a short grace, so an unrelated typeahead closing no longer triggers a retry that clicks the freshly opened widget shut; and containers that appear together are treated as one popup via their nearest shared ancestor, so a two-month calendar is handed over whole instead of one month at a time. A tie among suggestions fails only on a control that cannot hold typed text; on an editable combobox the typed literal stands and the result reports `plain-text`. The tools own the whole widget lifecycle and recover from a page that moves underneath them: a control the page replaces is re-found by identity — ranking same-named duplicates rather than refusing them, since an open picker routinely mounts a second copy of its own trigger — up to four times per fill, and once more by re-resolving the field name against a fresh observation. Ref identities survive an in-page route change and are dropped only when the document itself is replaced, so `browser_click` heals too. A disabled range start is re-tested against a reopened picker before being called unreachable, a paired range is given a moment to finish writing after release, and every failure names one concrete next step in its message. A date range is treated as one value rather than two dates, because pickers that spread a range over a check-in/check-out pair commit the pair as a unit and discard half of one on release: `browser_fill_form` collapses two dates into a single range fill when the page resolves exactly one control per side, a range is driven from the opening end even when the caller addresses the closing one, and half a range returns `WIDGET_RANGE_INCOMPLETE` naming the partner field and the call that works. Releasing is treated as part of committing, so the container a driver operated is released whether or not it was already open — leaving it open reported ranges as committed that the page had never accepted.

**Browser Widget Observability & Step Efficiency** _(updated: 2026-08-07 by fix)_
Source spec: [feature_browser_widget_observability.md](.spec-lite/features/feature_browser_widget_observability.md)
Browser-driven `do` runs now see dense real-site widgets with substantially fewer blind turns. The observation scanner takes accessible names from the locator engine's injected Playwright-port implementation (with a matching offline fallback). Names follow the accname "name from content" step rather than element text: a descendant contributes its own declared label in place of its text, `aria-hidden` subtrees contribute nothing, and inline content concatenates without an inserted separator. A control that labels itself through an inert child — the shape every major date picker uses for day cells — is therefore named for its date instead of the repeated bare number. The scanner labels each element with its nearest labelled widget `group`, prioritizes visible dialog/listbox/menu/grid scope, orders grouped elements panel-major and ungrouped ties by `(top, left)`, and raises the model-visible cap from 30 to 50 while preserving the protocol discovery cap at 30. Interactables expose only useful optional state: `disabled`, non-secret current `value`, `value_present` for withheld password/OTP/payment fields, and checked/expanded/selected state; every value still crosses user-input masking and profile sanitization. URL provenance attests origin + normalized path + parameter names while allowing already-attested query values to vary. Successful navigate/click/fill tools return a best-effort post-action observation, and repeated page text becomes `digest_unchanged: true` instead of reshipping the digest; internal uncapped form reads never consume model-visible digest state. The governed system prompt remains `agent-v7`, with compatible manifest validation for every prior version.

**Agent Grounding — Granted Context, URL Provenance, Real Form Filling** _(updated: 2026-08-03 by implement)_
Source spec: [feature_agent_grounding.md](.spec-lite/features/feature_agent_grounding.md)
Agentic runs no longer invent the two facts a web task most depends on — where the user is, and where a page lives. **User location is an explicit grant.** `profile.yaml` gains a `context` block (today one key, `context.location`, default `true`) gating a value composed from the new `locale.city` and existing `locale.region`; `yantra init` asks for it on an interactive terminal (skipped for `--json`, `--yes`, non-TTY, and re-runs), and `yantra prefs set context.location false` withholds it at any time. The per-run ambient block now states **every** fact on every run — date, timezone, and locale unconditionally, plus `- user location: <value>` or the literal `- user location: not available` — closed by a rule forbidding the model from deriving what it was not given. Denied and unconfigured render identically, so the model cannot detect a withheld value. **A goal that needs a location it does not have stops before any tokens are spent**: a deterministic pre-flight gate matches self-referential phrasings (`near me`, `in my area`, `where I live`, …) and exits 4 with a handoff whose remedy names either `locale.city` or the `context.location` grant, whichever applies; `"nearest station to Times Square"` carries its own anchor and is not gated. **`browser_navigate` refuses URLs no tool produced** (`URL_NOT_FROM_EVIDENCE`, checked before any budget is reserved): a run-scoped provenance record is seeded from user-supplied hosts (`--allow-host`, granted in full) and goal URLs, then extended by `web_search` hits, successfully fetched `web_fetch` pages, post-redirect navigation URLs, and intercepted popups. **`browser_form_fill` (a `do`-only tool) drives a multi-field form in one call**, re-observing uncapped between steps so autocomplete options and calendar days revealed by the previous step are addressable by visible name; it waits for a real `role="option"` suggestion rather than clicking a same-named marketing tile, drives calendar-button date fields as widgets (matching `"2026-08-05"` to a rendered `"August 5, 2026"`), stops at the first failing field with a typed error, never submits, and never handles credentials. The page scanner now sees `[role="option"]` elements at all. The system prompt is `agent-v6`, so `prompt_hash` changes for all agentic runs.

**Agentic Option & Budget Consistency** _(updated: 2026-08-02 by implement)_
Source spec: [feature_agentic_options_consistency.md](.spec-lite/features/feature_agentic_options_consistency.md)
`ask`, `research`, `do`, `run`, and `resume` now register and resolve one complete agent surface from `agent-options.ts`: provider, model, thinking, runtime-key auth, duration, token ceiling, tool timeout, identical-error retries, confirmation wait, and deterministic veto. Resolution is flag > environment > the new `profile.yaml` `agent.*` preferences > finite pinned defaults; duration parsing is shared and the retired per-command budget spellings are clean-break unknown options. Agent runs default to a 15-minute hard wall clock with an 80% publication wind-down, a 2,000,000-token ceiling, 3-minute tool and confirmation timeouts, and three retries. Tool-call counts remain audit data rather than caps, provider-cost stopping is removed, and timeouts fail only the affected retryable call; the retry breaker bounds repetition while preserving prior evidence for publication. Credential presence is probed offline without reading secret values: `ask`, `research`, and replay synthesis warn and degrade deterministically when unavailable, while `do` and live doctor smoke fail with `AGENT_AUTH_UNAVAILABLE`. Ordinary `doctor` now reports effective model, credential source, and five budgets with their configuration origins; live smoke selects its target through shared `--provider`/`--model` flags. Operational agent preferences are explicitly excluded from personalization context, and the canonical option/default reference lives in `docs/model-configuration.md`.

**Combined Web Research Tool** _(updated: 2026-07-19 by fix — evidence ledger: fetched sites become the published Brief's sources automatically)_
Source spec: [feature_combined_web_research.md](.spec-lite/features/feature_combined_web_research.md)
The agentic `web_search` tool now returns _evidence, not pointers_: one call runs the provider search, then fetches and extracts the top-N hits through the same `@yantra/core` per-source path the deterministic pipeline uses (`webResearch` over `processSource`), returning strongly-typed per-site content — `{ sites: [{ n, url, title, published_at, excerpt, text | capture_ref }], more_results: [{url,title,snippet}], failures: [{url, stage, reason}] }`. How many hits are fetched inline is set by `search.fetch_top` in `config.yaml` (integer 1–5, default 3; out-of-range fails loud at startup) and can be lowered per-call via `limit`; the unfetched tail is returned as snippet-only "more results". Every fetched URL passes the outbound URL policy and ethics gate individually — a per-URL refusal or fetch/extract miss becomes a per-site `failures` entry (stage `blocked`/`fetch`/`extract`), never a whole-tool error; the top-N fetches run in parallel so wall time stays ≈ one fetch round. Both snippets and fetched page content are untrusted input, sanitized and byte-bounded before the model sees them; oversized site text is stored as a `runs/<id>/captures/<ref>.txt` (mode 0600) capture reference. `web_fetch` is kept but narrowed to fetching one specific URL you already have (a direct link or one found inside fetched content). Every site either tool returns is also recorded in the run's **evidence ledger** (URL, title, excerpt, fetch/publication timestamps — sanitized and bounded at append), which `result_publish` attaches as the Brief's sources with excerpts, so the model never round-trips URLs through its own context. Per-command tool-call caps drop accordingly — ask 12 total / 6 per-tool, research 30 / 12, do keeps the global defaults (ask < research < do preserved) — and the default per-tool execution timeout rises to 60s to cover the search-plus-parallel-fetch round.

**Agentic Ask & Research Convergence** _(updated: 2026-07-28 by fix — uniform `--provider`/`--model`/`--thinking`/`--auth-secret` surface across ask, research, and do)_
Source spec: [feature_agentic_ask_research.md](.spec-lite/features/feature_agentic_ask_research.md)
All three agentic commands share one model-selection surface, registered from a single CLI module (`apps/cli/src/agent-model.ts`): `--provider <name>`, `--model <id>`, `--thinking <level>`, and `--auth-secret <ref>` are accepted identically by `ask`, `research`, and `do`. Previously only `do` exposed them, so `ask` and `research` could be pointed at a non-default (e.g. local Ollama) model only through `YANTRA_AGENT_PROVIDER` / `YANTRA_AGENT_MODEL`. Resolution is explicit flag > environment > pinned default (`anthropic` / `claude-haiku-4-5`); a blank provider, model, or secret reference is a typed validation failure (exit 1, `yantra.<command>.invalid-model` / `invalid-auth-secret`) rather than a silent substitution or a quiet downgrade from `runtime-key` to `managed` auth. On `ask` and `research` the selection is resolved before the execution-failure handler so an invalid override stays exit 1, and is skipped entirely on `--no-llm` runs, which never construct a provider session; their stderr status line now reads `search-provider=` (the web-search backend, distinct from the LLM `--provider`) and appends `model=<provider>/<id>` on agentic runs. `yantra ask`, `yantra research`, and `yantra do` use the same `runAgenticTask` lifecycle, `agent-v3` system prompt (a flow-neutral **Completion and failure** rule — never stall waiting for input: interpret a broad goal with the most reasonable interpretation and proceed; the per-run user prompt then carries the flow-specific `Interaction:` line — an unattended run states no user can answer, while an attended interactive `do` run (TTY, non-`--json`) states a user is present to approve protected actions but cannot answer open-ended questions — and injects an engine-derived **ambient context block** — current date with weekday, IANA timezone with DST-correct UTC offset, and locale, from the orchestrator's injectable clock and host environment, framed as authoritative so small local models don't answer date-sensitive goals from their training prior; user location is never inferred automatically — it belongs in the approved profile context), run-local session/audit artifacts, tool-call projection, usage ledger, and validated `result_publish` Brief contract whenever LLM reasoning is enabled. `CommandTaskProfile` applies registration-time least privilege: ask is web-only with workflow listing, research gets multi-source completion criteria and optional read-only browsing (`YANTRA_AGENT_RESEARCH_BROWSE=1`), while do keeps its full prior catalog. Each command resolves its profile explicitly at the CLI boundary, so `do` — like ask and research — honors its `YANTRA_AGENT_DO_*` budget env overrides instead of relying on the runtime's implicit default. A stuck-loop circuit breaker ends a run with a diagnostic `AGENT_TOOL_FAILED` after four consecutive identical tool failures (same tool + error code, no success between), so a weak model can no longer spend the whole budget retrying an impossible action. Per-command budget keys (`YANTRA_AGENT_{ASK|RESEARCH|DO}_{BUDGET_MS|MAX_TOOL_CALLS|MAX_CALLS_PER_TOOL}`) configure the caps; tool-call caps preserve ask < research < do defaults, while the agentic wall clock is **unlimited by default** for every command (local models are slow) and is bounded only by an explicit `--budget-ms` flag or `BUDGET_MS` env override — the CLI no longer clamps or injects the deterministic pipeline's timeout into agentic runs. `--no-llm` and `LLM_PROVIDER=none` select the existing deterministic ask/research paths before agent construction, retaining their artifact and golden-output contracts without credentials. The obsolete synthesis, research, client, and plan prompt stacks are removed and kept absent by boundary tests.

**Deterministic Workflow Tool & Promotion** _(updated: 2026-07-30 by fix — promotion also records `synthesis.use_llm`)_
Source spec: [feature_agent_workflow_bridge.md](.spec-lite/features/feature_agent_workflow_bridge.md)
Bridges the agent runtime and the deterministic workflow engine both ways. **Forward:** a `workflow_run` agent tool discovers saved workflows (`mode:list` returns a secret-free catalog — name/description/params/hosts only, never secret names/values, locator internals, or profile paths, via `WorkflowStore.listCatalog()`) and invokes one (`mode:run`) through the existing `RunOrchestrator`. Run mode validates the workflow exists (`WORKFLOW_NOT_FOUND`) and its params against declared types (`WORKFLOW_PARAM_INVALID` naming the param), then replays deterministically in its **own nested run directory** with no LLM inside; the sanitized, bounded result returns terminal status, step count, an outputs summary, and the nested `run_id`, which the parent's `tool-calls.jsonl` records as the audit join key. Confirmation checkpoints inside the workflow use the FEAT-026 connector bridge; non-interactive surfaces fail closed. **Backward:** every successful browser interaction (navigate/click/fill/extract, plus `observe`) is appended to a run-scoped trace (never opaque refs; secret _references_ for secret fills, never values; confirmation flags), written to `runs/<id>/trace.json` at finalize. Observations are recorded because an agentic run routinely _ends_ by observing — the digest already answers the user's question, so `browser_extract` is never called — and promotion needs to see that: mid-run observations are navigation aids and are dropped, while a **trailing** read (however many) collapses into exactly one terminal `extract` step, preferring a real `browser_extract` over an observation when both are present. Without it a promoted workflow clicked through and captured nothing. Promotion also **declares one output per capture** (`{{ capture.<name>.rows[0] }}`, or the whole `rows` array for a table), unwrapping the `ExtractionResultEnvelope` so the value reaches `outputs.json` rather than being captured and discarded. The locator recorded for a click/fill is the **ranked candidate chain the locator engine's own ranker derives from the live element** (`AgentBrowserController.locatorFor` → `window.__yantra.describeElement`): testid, then role + accessible name, then label/placeholder, then unique CSS, terminated by an absolute XPath. Sharing that one implementation with replay is what makes a promoted workflow replayable — the observation scanner's simplified role map calls `<select>` a `combobox` and every text-like input a `textbox`, where the resolver computes `listbox`, `searchbox`, and `spinbutton`, so a locator built from it pinned roles that could never match. The observed role/name remains a degraded fallback when the engine cannot describe the element, and locator derivation never fails the action it accompanies. `yantra do --save-as <name>` promotes that trace into a saved, lint-clean, replayable workflow (secret fills become declared `{{ secret:key }}` references; `requires_confirmation` flags preserved); promotion failure is reported but never fails the run. Promotion also **carries the run's synthesis intent**: when the run published a Brief, the saved workflow gets a `synthesis:` block holding the original goal (`length: medium`, `detail: standard`, `use_llm: true`), so replaying it reproduces the document that made the first run useful — wording and all, with no mode flag to remember — instead of reporting the raw trailing capture. `use_llm: true` is honest rather than assumed: reaching promotion means the agent published, and the agent is the model that wrote that report. A run that published nothing promotes without the block — there was no synthesis step to reproduce. An over-long goal is truncated to the schema's 512-character cap rather than failing promotion. A real-Chrome e2e proves the full round-trip: a fake-agent run's trace promotes to a workflow that `yantra run` replays green with no LLM, and an agent scripting `workflow_run` invokes a saved workflow whose nested run carries zero agent-session artifacts.

**Agentic Task Orchestrator & `yantra do`** _(updated: 2026-07-25 by fix — governed prompt bounds fallback attempts to one before failing early instead of inventing further alternatives; per-tool-call timeout raised to 90s so it doesn't clip the browser tools' own ~60s page-settle waits)_
Source spec: [feature_agentic_task_orchestrator.md](.spec-lite/features/feature_agentic_task_orchestrator.md)
`yantra do "<goal>"` now creates one auditable run and one fresh provider session, then lets the agent reason through only Yantra's policy-wrapped web, browser, script, and publication tools. The goal and profile context are redacted through the run's `UserInputVault` into indexed resolvable placeholders (`{{user:email:1}}`) rather than irreversible `[redacted-*]` markers — the per-run prompt states the pass-the-placeholder-verbatim contract when placeholders exist, tools receive the real values at the execution boundary, plain-text goals are no longer HTML-mangled (`&`→`&amp;`) by the sanitizer's cheerio pass, user-pasted signed URLs keep working, and the runtime-assembled fallback Brief resolves placeholders in the draft before publishing so the user's deliverable carries real values. The agent runtime—not the CLI—owns the governed `agent-v4` prompt (whose "Completion and failure" section now caps exploration at one materially different fallback before stopping and reporting the blocker, rather than continuing to invent alternatives — a broad or ambiguous goal is still not a stall reason), budgets (including a 90s per-tool-call ceiling, raised with headroom above the browser tools' own ~60s internal page-settle waits), completion nudge (a user-turn message built from run state: it names `result_publish` and its `{"brief": ...}` payload explicitly, recaps the consulted sources from the evidence ledger inline with a do-not-search-again instruction, anchors the model's previous message as the draft to publish, and — when the ledger is empty — states that no user is available so a broad or ambiguous goal is NOT a blocker; at nudge time with evidence in hand the runtime also **freezes the evidence phase**, so further `web_search`/`web_fetch` calls are rejected with `EVIDENCE_FROZEN` and the nudge turn is structurally publish-only; the manifest schema accepts every shipped `prompt_version` so older run artifacts keep validating), fail-closed confirmation bridge, event fan-out, typed outcomes, and exactly-once teardown; success requires a validated `result_publish` Brief. If the nudge turn still ends unpublished but the run holds both a draft answer and ledger evidence, the runtime **assembles and publishes the Brief itself** (draft as overview, ledger as sources with excerpts, `deterministic_fallback_used: true` plus an honest `notices` entry) and the run completes as published. Only when there is no draft or no evidence does the run fail: the `AGENT_COMPLETION_MISSING` failure carries a bounded, whitespace-collapsed excerpt of the model's post-nudge message (its self-stated blocker) into the CLI error and `report.md`, the **full** unvalidated final response is salvaged to `runs/<id>/result.md` (best-effort; noted in the failure message; not a validated Brief — the run still fails), and manifest/`events.jsonl` classify the failure as `validation_error` (consistent with the report) rather than `unexpected`. Terminal output streams bounded progress and compact tool status, while `--json` emits NDJSON and never prompts. The former discovery proposal/session/re-prompt stack and CLI-owned propose/act/observe loop are removed. Deterministic real-Chrome release scenarios cover publication, consented forms, CAPTCHA handoff, denial/timeout/non-interactive confirmation, prompt injection, off-policy fetches, and credential-shaped URL exfiltration; a live-provider scenario remains opt-in.

**Live Browser Capability & Tools** _(updated: 2026-08-12 by fix — a tab the site opens on its own domain is now followed rather than closed, because a search that finishes in a new tab leaves its results in that tab and the address alone often cannot rebuild them)_
Source spec: [feature_agent_browser_tools.md](.spec-lite/features/feature_agent_browser_tools.md)
Agent runs now lazily launch one system-Chrome page in a fresh ephemeral profile and expose five policy-wrapped tools: `browser_navigate`, `browser_observe`, `browser_click`, `browser_fill`, and `browser_extract`. The production Puppeteer/CDP locator host survives navigation and is shared by agent actions and deterministic replay. Observations return bounded, sanitizer-processed text plus ranked opaque refs with a **stable lifecycle**: a ref stays valid from the observation that minted it until the main frame navigates to a new document — successful fills/clicks and popup interception do NOT invalidate sibling refs, so observe → fill → fill → click works from a single observation. Re-observing the same document reuses the same ref id for the same logical element (matched by role + name + duplicate ordinal) while refreshing the underlying handle, so retries see consistent ids; ref numbering stays monotonic across the run and identity reuse resets on navigation, so an id from an old document can never alias an element on a new one. Genuine staleness (the node left the DOM) is detected per-action via a connectivity check and returns `STALE_ELEMENT_REF`; the actionability pre-flight is deliberately limited to scroll-independent facts (connected, laid-out box, not `display:none`/`visibility:hidden`, not disabled → `ELEMENT_HIDDEN`/`ELEMENT_DISABLED`) — the former centre-point `document.elementFromPoint` occlusion probe is gone because its viewport-relative coordinates rejected **every element below the fold** as occluded even though Puppeteer scrolls the target into view before acting; a genuinely covered element is now clicked through to whatever covers it, exactly as a real user's click would be, and the agent sees that outcome by re-observing; a click whose form-submit/navigation destroys the execution context mid-call is recognized as a landed click and returns the destination page instead of surfacing `TOOL_EXECUTION_FAILED`. **Every action holds its result until the page stops moving** — and this settling now lives in a shared `PageSettler` (`browser/page-settle.ts`) used by both the agent tools and deterministic workflow replay, so a replayed step waits exactly the way the agent did and any tuning lands on both paths at once: a navigation watcher installed before the action catches main-frame navigations however the site schedules them (sync handlers, `setTimeout` redirects, async validation → submit — previously anything starting later than ~30ms after the action was missed and the agent's next tool call raced the navigation), waits bounded for the commit and DOMContentLoaded, follows client-side redirect chains, and finishes with a bounded network-quiet wait so fetch/XHR-driven SPA updates land before the agent's next observation; every phase is bounded (post-action settling, read-settling for `browser_observe`/`browser_extract`, and the network-quiet tail are each sized to ~60s, since a real-world result page such as a carrier tracking page commonly takes 10-30s to populate via an async fetch) and a page that never settles degrades to a result rather than an error. Those ~60s figures are **ceilings, not the cost of a call** — a settled page returns in well under a second — because the network-quiet wait keeps its own in-flight accounting instead of reading Puppeteer's counter: renderer-served requests (`blob:`, `data:`, `filesystem:`), whose completion is reported to the consuming context rather than the page, and requests still open past a staleness window (SSE, long-poll, a hanging beacon) never count toward "busy". Reading the raw counter instead made strict idle unreachable on any site carrying a blob-backed bot-protection or analytics worker — most commercial sites, ups.com among them — so **every** browser tool call ran to the full cap (measured: navigate 61.6s, observe 60.4s, extract 60.0s per call). Clicks are dispatched as a user-shaped held press (scroll-into-view + trusted CDP mouse events with a 40ms down–up hold). Popups — whether declared (`target=_blank`, inline `window.open`) or opened by dynamically wired event listeners — are captured and waited (bounded) to reach their real URL instead of being read at `about:blank`. **A popup the acting page opened on its own site is held open and, after `browser_click` puts it through exactly the checks `browser_navigate` applies (URL provenance, host/URL policy, the ethics gate), becomes the run's page**: the opener is closed, refs are invalidated as after any navigation, site overlays are dismissed, and the result reports `switched_to_new_tab`. Handing back only an address was not enough — a search that submits into a new tab leaves its results _in that tab_, behind a session token or server-side state, and the opener is frequently redirected to a partner in the same gesture (KAYAK to booking.com/vrbo.com), so following the returned URL loaded the partner site or an empty listings shell and the run published the wrong dates or gave up on the site. Same-site is host containment after dropping `www.` (so `google.com` → `accounts.google.com` qualifies and `bbc.co.uk` → `evil.co.uk` does not); anything else, and anything not `http(s)`, is closed on sight and surfaced as `popup_intercepted` for the model to navigate to explicitly. At most one unadopted tab is ever held, and the next navigate/click/fill closes it. **The intercepted URL, the held tab's live URL, and the URL an action actually landed on are recorded as URL provenance by every action tool** (`browser_click` as well as `browser_navigate`) — previously only navigation recorded provenance while popups are opened by clicks, so a site whose Search button opens results in a new tab handed the agent a URL it was then refused as `URL_NOT_FROM_EVIDENCE`. **Overlays the site itself raises are dismissed after a navigation**: a rendered, floating dialog/listbox/menu/grid is sent Escape (at most three presses, stopping as soon as one closes nothing) and the count is returned as `overlays_dismissed` — a booking site that serves its date picker already open otherwise contributes ~170 day cells to a 50-element observation and the destination field and search button are structurally invisible, so `browser_fill_element` answers `FORM_FIELD_NOT_FOUND` for "Destination" while listing dates as what is available. Ownership bounds it: statically positioned page content (results marked up as `role="grid"`) is never Escaped, an overlay the agent opened itself by clicking is left alone, and widgets the fill engine opens are still released by the fill engine; JS dialogs can never deadlock the page: `beforeunload` is accepted so agent-initiated navigation proceeds, alert/confirm/prompt are dismissed (never silently accepted) and surfaced as `dialog_intercepted` on the action result. `browser_fill` fills a native `<select>` by option label or value with the input/change events frameworks expect (`OPTION_NOT_FOUND` when nothing matches), types with human-scale per-key pacing that drops for long values so a large fill cannot blow the tool budget, and watches for fill-triggered navigation the same way clicks do. `browser_fill` accepts either a plain string (typed as a non-secret literal — the shape small local models reliably produce, so they no longer loop on "value must be object") or a tagged secret-reference object; a `{{user:...}}` placeholder in the string resolves to the real user-provided value at the execution boundary (the field receives the actual email/phone/etc., not the redaction marker), the persisted trace records only the placeholder form, and a credential-shaped resolved value is rejected as `SECRET_SHAPED_LITERAL` exactly like a raw one. `browser_extract` takes an **optional** `kind` that defaults to `content` and resolves the obvious synonyms (`text`/`page`/`body`/`article`/`readable content` → content, `tables`/`first table` → table, case- and separator-insensitive); anything else is refused inside the tool with a retryable `INVALID_INPUT` that names the two accepted kinds, because the provider-side schema check runs before Yantra's middleware and its literal-union rejection ("must be equal to constant") never told the model what to send instead. A successful `content` extraction also **records the page in the run's evidence ledger** (URL, title, bounded excerpt, fetch timestamp), so `result_publish` attaches it as a Brief source: a browser-driven `do` run reads its answer off pages it clicked through to, and previously only `web_search`/`web_fetch` fed the ledger, so such a run published the search hop — or nothing — as its sources while every fact came from the extracted page. Recording is best-effort and dedupes by URL (a page with no fetchable `https?:` URL is skipped rather than turned into a junk source), and a `table` extraction records nothing (no title or prose to excerpt; the page enters the ledger when its content is read). Website secret fills require trusted host metadata before resolution and never return resolved values, while protected clicks remain confirmation-gated and large extracts become capture references. Real-Chrome fixtures cover navigation, ref stability across observations/actions, stale refs after reload/navigation and node removal, single-observation form fill and submit, popup interception without ref staling (declared and dynamically wired), delayed post-click navigations, client-side redirect chains, dialog auto-handling, fetch-driven DOM updates settling before extraction, `<select>` fills by label/value, long-value overtyping, actionability failures, host mismatch, artifact canary scanning, and table extraction.

**Safe Web & Utility Tools** _(updated: 2026-08-04 by fix — the evidence ledger also carries pages read through the browser; a budget bounds tool use, not the run: `result_publish` is exempt from the run-wide cumulative caps, and only wall-clock exhaustion aborts a run)_
Source spec: [feature_agent_web_tools.md](.spec-lite/features/feature_agent_web_tools.md)
Yantra exposes four registered agent tools — `web_search`, `web_fetch`, `script_run`, and `result_publish` — each wrapped by a **mandatory middleware pipeline** the model cannot bypass: closed-schema input validation (violations return `INVALID_INPUT` naming the failing field's JSON pointer) → user-input placeholder resolution (`{{user:...}}` tokens from the run's `UserInputVault` become the real user-provided values at the execution boundary, mirroring opaque secret refs) → budget/timeout/abort → host/ethics/scope policy (+ post-publish action-phase latch) → confirmation gateway → domain op (AbortSignal threaded) → user-input masking (real values echoed by pages return to the model as their stable placeholders, and failure messages/details are masked the same way) + sanitizer + per-result byte bounding → stable tool result → audit projection. Expected failures return stable `error_code`s with a `retryable` flag; unexpected exceptions are genericized to `TOOL_EXECUTION_FAILED` with no secret/raw-content leak; sanitization and confirmation are not agent-callable. A run-scoped `BudgetTracker` enforces total/per-tool calls, per-tool timeout, per-result and cumulative agent-visible bytes, navigation/host caps, and an **opt-in** wall-clock cap (unlimited by default; bounded only via `--budget-ms`/`YANTRA_AGENT_<CMD>_BUDGET_MS`). **A budget bounds tool use, not the run**: `result_publish` — the run's only exit — is exempt from the run-wide cumulative caps (`totalToolCalls`, `maxBytesPerRun`) but still bound by its per-tool cap and the wall clock, so a run that spent its budget gathering evidence can no longer be denied its own publication (previously twelve successful searches/fetches would exhaust a 12-call budget and the thirteenth call, `result_publish`, failed with `BUDGET_EXHAUSTED`, discarding the entire run); and only wall-clock exhaustion aborts the session, while every count-based cap (`total-calls`, `per-tool-calls`, `cumulative-bytes`, `navigations`, `hosts`) fails just that call — carrying the tripped limit in `details.budget_limit` and telling the agent to publish what it already gathered — so the run reaches its completion nudge instead of being thrown away; the outbound-URL policy length-caps, https-restricts, credential-shape-scans (`sk-`/`ghp_`/`AKIA`/`eyJ…`), and host-budgets every fetch URL, auditing every decision. `web_search` is now a combined search-that-fetches tool (see **Combined Web Research Tool**) returning per-site extracted content plus a snippet-only tail and per-site `failures`, not just `{url,title,snippet}` pointers; `web_fetch` (narrowed to fetching one specific already-known URL) runs the ethics gate (robots/blocklist/rate limit — no evasion path), a content-type allowlist, and a streamed size limit, fetches through the same hybrid HTTP→headless-browser fallback as deterministic ask/research (bot-refused 401/403 responses and script-rendered shells escalate to a browser render instead of failing), returns `EXTRACTION_EMPTY` with fetch-a-specific-article-URL guidance when Readability finds no article (index/hub/media pages), and stores large extracted content as a `runs/<id>/captures/<ref>.txt` capture reference; `script_run` executes only code-defined, allowlisted transformation scripts (`table_normalize`, `dedupe_lines`, `json_pick`) with validated args out-of-process (worker with time/memory/output caps — trust boundary is the registry, not OS sandboxing); `result_publish` accepts agent-authored content — `{title, overview, key_findings}`, with `title` (non-empty) and `overview` **schema-required** so a payload missing them is rejected as `INVALID_INPUT` naming the field before the publisher runs — and deterministically assembles the formal protocol Brief around it (document/task ids, contiguous source numbering, hosts, fetch timestamps, `synthesis: 'llm'` metadata with the owning run id); **sources are ledger-authoritative**: when the run's evidence ledger has entries (every site `web_search`/`web_fetch` returned, plus every page a `browser_extract` content read consulted), those entries become the Brief's sources with excerpts in consulted order, model-supplied `sources` are ignored, and findings are published as editorial commentary (ad-hoc citation numbers are stripped rather than mis-attributed — which is why the renderers show the editorial mark only when a Brief also carries a cited finding); model-supplied sources are honored, with full citation-integrity validation, only when the ledger is empty (a run that published without reading a page); a complete protocol Brief (detected by `brief_id`/`schema_version`) still passes through untouched for internal callers. Either shape is validated against the protocol schema (citation integrity included; uncited findings default to editorial commentary, an explicit `editorial: false` without citations is rejected), then `brief.json/md/html` are written and the action phase closes (exactly one successful publication — a second attempt is `ALREADY_PUBLISHED`, later mutating calls are `ACTION_PHASE_CLOSED`, read tools stay available). `createYantraTools(runServices)` registers the tools with unique names in deterministic name-sorted order (feeding a stable `tool_catalog_hash`); Pi built-in `bash`/`read`/`write`/`edit`/`grep`/`find`/`ls` tools are asserted absent from the active catalog.

## Research

**Deep-Research Mode (`yantra research`)** _(updated: 2026-07-03 by implement)_
Source spec: [feature_deep_research.md](.spec-lite/features/feature_deep_research.md)
`yantra research "<topic>"` runs a **bounded multi-hop** loop (`packages/core/src/research/`) where `ask` runs one: `search → fetch → extract → pool → interim synthesis for gap analysis → generate follow-up queries → repeat`, then one final long-form synthesis over the whole corpus. Hop 1 maps the topic; later hops target the coverage gaps the synthesis surfaced. Everything is budgeted by a single `BudgetTracker` (injectable clock, no real sleeps) across four dimensions — hops (`--depth {1|2|3}`, default 2), sources (`--max-sources`, default 24), wall-clock (`--budget-ms`, default 180s), and LLM calls (`--budget`, default 12) — and the loop terminates cleanly (`coverage_met` → `max_hops` → budget dimension → `no_novel_queries`), emitting an honest partial Brief with a `budget_exhausted` notice rather than hanging or truncating silently. A `SourcePool` dedups exact (tracking-param/fragment/trailing-slash-normalized URL) and near-duplicate (shared FEAT-014 TF-IDF cosine ≥ 0.85) articles and caps sources per host (default 3, rank-preferential) so one domain can't dominate. A `CoverageTracker` seeds subtopics from the interim synthesis (section headings + recurring named entities), marks each covered once ≥2 pooled docs evidence it, and exposes a heuristic `metadata.coverage` score plus the uncovered gaps. Follow-up queries come from `FollowUpQueryGenerator`: deterministic template expansion over uncovered subtopics (novelty-filtered, capped at 3/hop) or, when a model is wired, an LLM path whose interim overview flows through the single `sanitize()` chokepoint before send and whose output is validated (plain-string/length/charset bounds) with deterministic fallback on any failure — so `--no-llm` (or `LLM_PROVIDER=none`) works end to end. Per-source failures isolate to notices (shared `processSource`, now also used by `AskPipeline`); a search-provider error mid-hop degrades that query to zero results and continues. Output flags mirror `ask` (`--detail`, `--format`, `--length`, `--open`, `--search-provider`, `--json`); each hop also writes a `research-state.json` snapshot (queries, kept/fetched counts, coverage, remaining budget) and a `research_hop_completed` event for post-mortems. Exit codes: 0 ok, 1 validation (e.g. `--depth 4`), 2 execution failure.

## Plan Executor

### Plan Executor & Step Verbs (FEAT-005)

The `Executor` class drives a `Plan.steps` array to completion, maintaining an `ExecutionContext` that carries all mutable state for one run: captures, retry budgets, an event bus, a checkpoint store, and an ethics gate. Each step is dispatched through a `STEP_DISPATCH` map (navigate, click, fill, extract, wait_for, assert, branch, loop, call_workflow, llm_summarize). Step results are a discriminated union — `completed`, `retried`, `failed`, `handoff_requested`, `ethics_refused`, or `jump` (for branch goto semantics). The executor enforces a `MAX_TOTAL_STEP_EXECUTIONS` guard to prevent infinite loops.

**Page settling** is shared with the agentic tools via `PageSettler`: `navigate` follows follow-on redirects before completing, `click`/`fill` install a navigation watch _before_ dispatching and hold until the page stops moving (late navigations, redirect chains, then a bounded network-quiet wait), and `extract`/`assert` wait for the document to finish loading before reading. Replay previously had none of this — `click` returned the instant `elementHandle.click()` resolved — so on a real site (a tracking page whose result arrives via a fetch 10-30s later) the next step read the pre-click document and the workflow completed having captured an empty shell. Contexts with no Puppeteer page (test fakes, non-Puppeteer providers) get a null settler and run without settling, exactly as before.

**Retry budgets** are three independent token counters (`locatorAttempts`, `stepAttempts`, `workflowAttempts`). `consume()` throws `BudgetExhaustedError` past zero. `snapshot()/clone()` support checkpoint-based resume. **Captures** (`InMemoryCaptureStore`) accumulate `extract` step output under `step_id` keys; values >64 KB are represented as sidecar references in snapshots. **Extraction kinds** are `string | number | boolean | date | money | readable`; `readable` runs the same `ReadabilityExtractor` the agent uses for its own page digest and falls back to the element's rendered `innerText` when Readability finds no article — which is the common case for the app-like pages workflows are recorded against (a tracking result, an order summary). `string` on a page-level locator returns `textContent`, i.e. nav, cookie banner, footer, and the source of every inline `<script>`, which is why promotion pairs a whole-page locator with `readable`. **Scope enforcement** (`checkScopeViolations`) preflights the entire plan before execution using `ALLOWED_VERBS_BY_SCOPE` from protocol; scope violations abort before step 1 runs.

**Checkpointing** (`FilesystemCheckpointStore`) writes atomically via `.tmp` + `fs.rename` after each successful step. Resume (`resumeFrom`) restores capture state from the snapshot and re-enters the step loop from the checkpoint's `after_step_idx + 1`. **Events** (`JsonlEventBus`) buffer in memory and flush to `events.jsonl` every 200 ms (debounced), with a synchronous `flush()` forced before checkpoint writes. **Reports** (`writeReport`) produce a Markdown call-log at `report.md`.

**Ethics gate** (`EthicsGateImpl`) enforces blocklist first (synchronous) and rate-limiter last (in-process per-host token bucket, injectable `Clock` for tests). Robots.txt enforcement is now opt-in via config (`ethics.robots_enabled: true`); when enabled it runs between blocklist and rate-limiter with 24h per-host caching (fail-open for 404 per RFC 9309, fail-closed for timeouts/5xx). `handleNavigate` calls the gate before any `page.goto`. **Value resolution** (`ValueResolver`) handles `literal`, `param`, `capture`, and `template` refs; secrets use a separate `resolveSecret()` path that returns a `{plaintext, zero}` pair — secrets are never returned by `resolve()` and never appear in step_completed event payloads.

The `FileUsageWriter` batches `UsageCall` records and persists them as a `UsageLedger` at `usage.json`. Stub handlers for `call_workflow` (FEAT-010) and `llm_summarize` (FEAT-011) return structured failures pointing to those features.

## Browser Engine

### Locator Engine & Auto-Wait (FEAT-004)

The locator engine resolves named UI targets via ordered **candidate chains** (each candidate is a typed `LocatorIntent`). `LocatorResolverImpl.resolve(chain)` walks candidates in order, calling the browser-side InjectedScript via `InjectedScriptHost.call()`. In strict mode (default) a candidate matching >1 element resolves nothing and the walk **continues to the next candidate**, so a broad candidate can hand off to a narrower one; ambiguity is reported only if the whole chain is exhausted, and it outranks `not_found` in the result so the author is told "your locator matches 3 elements" rather than "nothing matched". A non-strict chain accepts the first of several matches. Per-candidate timeouts fall through to the next candidate rather than aborting. A `LocatorResolutionEvent` is emitted via the optional `LocatorEventSink` after every resolve call carrying chain name, outcome, winning index, and duration (no DOM content — security invariant enforced by property test).

`resolveActionable(chain, host, options)` wraps the resolver in a Playwright-style auto-wait loop: backoff `[0, 20, 50, 100, 100, 500, 500, …]` ms, comparing two `getBoundingRect` snapshots 100 ms apart for stability. `options.requirement` selects how much of the actionable contract the caller needs — `actionable` (all four conditions; click/fill), `visible` (attached + visible + enabled + stable; extract/assert and `wait_for: visible`), or `attached` (presence only; `wait_for: attached`). Only pointer input demands `receivesEvents`, whose centre-point hit test can never be satisfied by an element taller than the viewport. `frame_detached` throws immediately; ambiguity is retried until the deadline (a mid-render duplicate often resolves itself) and then throws `LocatorAmbiguousError`; otherwise the deadline throws `LocatorNotActionableError` carrying the last `ActionableState`.

The **InjectedScript bundle** (`dist/injected.bundle.js`, IIFE, < 50 KB, no `require()`, no `process.env`) is built by esbuild from `src/locator/injected/index.ts` and registers `window.__yantra`. Eight resolution strategies are implemented in the injected layer: `role+name` (WAI-ARIA computed role + accessible-name algorithm, ported from Playwright Apache-2.0), `testid` (configurable attribute aliases), `label` (`<label for>`, implicit wrap, aria-labelledby, aria-label), `placeholder`, `text` (normalized + regex), `css` (with a unique-CSS generator using stable-class heuristics), `xpath`, and `relative` (all 7 RelativeRelation variants). A match set of more than one element is **narrowed to its visible members** when any are visible — a preference, not a filter, so an all-hidden match set is returned intact and `wait_for: hidden`/`detached` still observe their target. `CSS.escape` and `elementFromPoint` are used browser-side.

The **candidate ranking algorithm** (`ranking.ts`, browser-side) scores candidates by base weight (testid=1.00, role=0.90, label=0.75, placeholder=0.60, css=0.45, relative=0.30, xpath=0.10) × specificity × stability, sorts descending, and caps to `topN` (default 5). Ties break by kind order for determinism. It is strictly read-only against the live page. It is exposed on the bundle as `describeElement(el)` and is the **single source of durable locators for both recording and replay**: recording a locator any other way (a simplified role table, a separate accessible-name implementation) pins a role or name the resolver would never compute for that element, which fails replay against a page that has not changed.

The `intent-codec.ts` module provides `encodeIntent`/`decodeIntent` for the JSON ↔ `LocatorIntent` round-trip (RegExp serialized as `{ __isRegExp, pattern, flags }`). Errors (`LocatorNotFoundError`, `LocatorAmbiguousError`, `HitTargetInterceptedError`, `LocatorNotActionableError`, `FrameDetachedError`, `LocatorInvalidSelectorError`) all carry structured context for failure reports.

### Chrome Launcher & BrowserProvider (FEAT-003)

`LocalBrowserProvider.launch()` spawns system Chrome over CDP pipe transport (`--remote-debugging-pipe`, no WebSocket port), returning a `LocalBrowserSession`. It validates `LaunchOptions` via Zod, resolves the profile via `LocalProfileStore`, discovers Chrome with `detectChrome()`, and rejects unsupported versions (< 120). The core launcher applies one user-simulation policy to every launch (agentic tools, deterministic replay, browser fetch, and scraped search): platform-consistent desktop UA derived from the detected Chrome major, host locale, and `AutomationControlled` compatibility. These managed switches cannot be overridden through `extraArgs`, preventing per-flow drift. Crash events are detected via child-process `exit`, emitted as `BrowserCrashedError`, and ephemeral profiles are cleaned up best-effort. The session's `newPage()` rejects if the session is closed or crashed.

`detectChrome()` discovers Chrome per-platform without ever opening a browser window. On macOS/Linux it reads the version by running `<chrome> --version`. On Windows it deliberately does **not** execute `chrome.exe` (which on Windows prints nothing and instead opens a visible browser window); instead it locates the binary via the App Paths registry key or standard install paths and reads the version from the versioned `Application\<version>` subfolder, falling back to PowerShell `VersionInfo.ProductVersion`. The `reg query` probe discards child stderr so a missing registry key does not leak an error to the console. _(updated: 2026-05-19 by fix)_

`LocalProfileStore` manages per-workflow profile dirs (`~/.local/share/yantra/profiles/<name>` with chmod 0700 on Unix), ephemeral dirs (`<tmpdir>/yantra-<uuid>`), and explicit absolute paths. It enforces a refused-path guard that rejects the user's real Chrome profile roots (macOS Library, Linux .config, Windows AppData).

`yantra doctor` runs seven checks (chrome.detected, chrome.version_min, datadir.writable, datadir.permissions, cachedir.writable, keychain.reachable, indexdb.writable), never throws, caches results for 1 hour at `~/.cache/yantra/doctor.json` (mode 0600), and returns a `DoctorReport` with an `overall` rollup of ok/warn/error. The `indexdb.writable` check opens the SQLite index (auto-rebuilding from the run tree if it was corrupt → warn) and probes a write. Permission checks walk per-workflow profile subdirs and report offenders in `details.offenders`.

Path helpers in `paths.ts` honor `XDG_DATA_HOME`/`XDG_CACHE_HOME` on Linux and `%LOCALAPPDATA%` on Windows.

**Configurable Search Provider Registry** _(updated: 2026-08-04 by fix — DuckDuckGo sponsored rows are dropped, and a browser-rendered HTTP error page is no longer reported as a successful fetch)_
Source spec: [feature_search_registry.md](.spec-lite/features/feature_search_registry.md)
Search is a registry of first-class providers keyed by name — `google`, `duckduckgo`, `brave`, `tavily` — one descriptor per provider in `search/registry.ts` (the retired `browser` name is gone). `resolveSearchProvider()` picks one by precedence `--search-provider` flag > `SEARCH_PROVIDER` env > `config.search.provider` > `auto`. ## Recorder

### Recorder Phase 1 (FEAT-008)

FEAT-008 is implemented across `packages/protocol/src/schemas/recording-draft.ts` and `packages/core/src/workflow/recorder/`. A `RecordingSession` orchestrates a visible Chrome browser session (via puppeteer-core), injects a CDP overlay script into every page, and produces a `draft.json` artifact containing all captured user actions.

The **protocol schema** (`RecordingDraftSchema`, `CapturedActionSchema`) lives in `@yantra/protocol` and enforces the redaction guarantee at the type level: `fill.raw_value` is `z.literal('<redacted>')`, so any attempt to persist an unredacted fill value is a compile-time error. The pre-redaction types (`RawCapturedActionInput`, `RawFillAction`) are internal to the `redactor.ts` module and not re-exported from the recorder barrel.

The **overlay** (esbuild IIFE bundle, built with `pnpm --filter @yantra/core build:recorder-overlay`) runs in-page and captures `click`, `input` (250 ms debounce), `change`, and `keydown(Enter)` events. For each captured action it calls `buildElementDescriptor()` (ARIA role + accessible name + sanitized attr sample + XPath debug string) and forwards the payload to Node via a CDP `Runtime.addBinding` channel. The overlay also draws a fixed-position recording indicator (red dot + action counter) and advises the user to "stop with Ctrl+C in the terminal".

The **redactor** (`DefaultCaptureRedactor`) is the only code that reads `raw_value`; it replaces it with the sentinel `'<redacted>'` and records `value_length` (code-point count). Defense-in-depth `defangAttrValue()` strips credential-shaped strings (sk-, sk-proj-, ghp*, AKIA, eyJ, xoxb-, gho*, glpat-) from element attribute samples before they are persisted.

**Session lifecycle**: `RecordingSession.start(name)` generates a time-ordered recording ID, calls `RecordingStore.create()`, launches Chrome headful, registers the CDP binding and overlay, sets up popup attachment (`PopupHandler`), cross-origin iframe detection, and starts the `IdleWatcher` (default 5-minute timeout, fires `IdleTimeoutPromptEvent`). `RecordingSession.stop(reason)` assembles and Zod-validates the draft via `assembleDraft()`, writes it atomically to `draft.json`, removes the partial draft, closes the browser, and destroys the ephemeral profile unless `keepProfile` was set. `abort()` preserves the profile for post-mortem.

**Crash safety**: `appendAction` + `FileSystemRecordingStore` write `draft.partial.json` atomically (`.tmp` + `fs.rename`) after every captured action. If the process crashes before `stop()`, the partial draft survives on disk.

**Tests** (all tagged `@no-llm`): 66 unit tests across `redactor.spec.ts` (incl. 500-run fast-check property test), `descriptor-builder.spec.ts` (jsdom, 22 tests), `draft-builder.spec.ts` (10 tests), `store.spec.ts` (8 tests), `idle-watcher.spec.ts` (7 fake-timer tests), `session.spec.ts` (4 integration + state-machine tests).

Source spec: [feature_llm_assisted_replay.md](.spec-lite/features/feature_llm_assisted_replay.md)
`yantra run` accepts the same `--provider` / `--model` / `--thinking` / `--auth-secret` surface as `ask`, `research`, and `do`, and **no opt-in mode flag** — whether a model writes the Brief is the workflow's declaration (`synthesis.use_llm`), so the command produces what the workflow was saved to produce every time it is typed. `--no-llm` (and `LLM_PROVIDER=none`) is a veto that forces the deterministic path even for a declaring workflow, spelled exactly as on `ask` and `research`. Model flags choose _which_ model a declaring workflow gets and never opt one in, so a stray `--model` or a `YANTRA_AGENT_*` environment cannot quietly open a provider session; an invalid provider/model is resolved before execution and exits 1 as a validation failure. When a run produces a Brief it renders through the same terminal path `ask` uses instead of dumping raw captures, and `--json` includes the document alongside the artifact paths. A run with no `synthesis:` block renders its outputs exactly as before; the empty-outputs hint now also points at the `synthesis:` block. Two surfaces are **hard zero-LLM** regardless of flags: scheduled/daemon fires and nested `workflow_run` invocations. `yantra resume` inherits the original run's strategy from `manifest.synthesis`, so a resumed run neither acquires a model it never had nor downgrades one it did; a run that wanted a model and had to fall back is offered one again, so a transient provider failure cannot permanently downgrade a workflow.

**CLI Polish, Audit, Distribution** _(updated: 2026-05-16 by implement)_
Source spec: [feature_cli_polish_distribution.md](.spec-lite/features/feature_cli_polish_distribution.md)
Caps the MVP with the user-visible command surface: `yantra ask`, `run`, `resume`, `list`, `show`, `lint`, `audit`, `report`, `doctor`, `init` — all behind a single `yantra` binary with a documented exit-code map (0 OK / 1 validation / 2 execution / 3 environment / 4 user-handoff). The `--json` flag emits a stable `schemaVersion` envelope on every command for scripting (currently `"0.2"`, tracking the protocol schema version; `"0.1"` consumers remain compatible — the bump was additive). `yantra audit <run-id>` builds a structured audit report (trust narrative + agent/secret/engine sections) from `manifest.json` + `agent.jsonl` + `secrets.jsonl` + `events.jsonl` without ever surfacing secret values. `yantra report <run-id>` prints (or `--open`s) the per-run `report.md` verbatim. `yantra doctor` extends FEAT-003 v0 with overall ok/warn/fail rollups and remediation hints.

The `ConnectorIO` interface in `apps/cli/src/connector-io.ts` is the load-bearing abstraction that decouples the CLI surface from the underlying executor — Phase 2 connectors (WhatsApp, email, web) plug in by implementing this single interface. `TerminalRenderer` and `JSONRenderer` are interchangeable implementations of `OutputRenderer`; `buildRenderOpts(flags)` picks between them at process start based on `--json` / TTY detection / `NO_COLOR`. The runtime helper (`apps/cli/src/runtime.ts`) wires the workflow orchestrator dependency graph (ethics gate, browser provider, keychain, profile store, workflow store, run store) so individual subcommands don't repeat the boilerplate.

Verification: 29 unit tests across `apps/cli/src/` (commander setup, exit-code map, global-flags parser, ConnectorIO contract, audit-builder round-trip, auto-detect for `show`); 7 e2e tests in `e2e/cli-commands.spec.ts` covering the no-args banner, `list runs|workflows --json` empty roots, `audit`/`report` not-found paths, and `init --provider {none|invalid}`. Distribution channels (npm `bin: { yantra: dist/bin.js }`, Homebrew tap, Scoop bucket) and the bundled-CLI release pipeline are deferred to the first stable release.

## Consent & Safety

**Human-in-the-Loop Action Gateway** _(updated: 2026-07-04 by fix)_
Source spec: [feature_human_in_the_loop.md](.spec-lite/features/feature_human_in_the_loop.md)
Steps flagged `requires_confirmation` (legal on `click`, `fill`, `navigate`) make the executor **pause** before any side-effect machinery, emit a structured `ConfirmationRequest` (action kind, host, description, expected cost, consequence), persist it to `confirmations.jsonl`, and block on an injected `ConfirmationGateway` until a human resolves it. Consent is **unforgeable by type** — the `ConfirmationDecision.decided_by` union has no agent variant (`user_interactive | user_cli_confirm | timeout` only). Deny or timeout terminates the run as a user-handoff abort (exit 4) with a structured `report.md`. Interactive `yantra run` / `yantra resume` (TTY, not `--json`) inject an `InteractiveConfirmationGateway` that renders a consent card with a `[y/N]` prompt defaulting to deny (fail-closed) and proceeds in-process on a grant; `--json` / non-TTY runs wire no gateway, so a flagged step fails closed as a user-handoff abort rather than self-authorizing. `yantra confirm <run-id> {grant|deny}` records a decision for a pending request (the async park → `confirm` → `resume` grant-lookup that lets a resumed run consume a prior grant instead of re-requesting is still in progress — tracked in `.spec-lite/TODO.md`). The annotate flow offers the flag per kept `click` action (defaulting yes for purchase-shaped clicks via a buy/pay/book/order/submit heuristic), and a new `CriticalActionWithoutConfirmation` lint rule warns when a purchase-shaped step lacks the flag. A chaos suite verifies three enforcement layers: 100% consent requirement, no agent pre-satisfaction, and audit completeness in both `confirmations.jsonl` and `events.jsonl`.

## Security Envelope

**Guaranteed User-Input Masking** _(updated: 2026-08-05 by implement)_
Source spec: [feature_user_input_masking.md](.spec-lite/features/feature_user_input_masking.md)
Users can wrap any run-scoped value in `@{...}` or a closed tagged form such as `@password{...}` to guarantee it remains usable by tools without entering model prompts, run artifacts, or promoted workflows. English keyword look-around and checksum-gated shape detection add best-effort protection for unmarked values, while malformed markers fail as exit-1 validation errors before a run is created. Short-value echo warnings remain advisory and are suppressed for JSON output.

### Security Envelope (FEAT-006)

FEAT-006 is implemented across `packages/core/src/sanitizer`, `packages/core/src/secrets`, `packages/core/src/audit`, and `scripts/ci-static-check.ts`. The sanitizer now has a single chokepoint `sanitize(payload, profile, hostHint?)` with deterministic transform ordering, profile matrix (`public`, `read-only-data`, `authenticated`), host override support, transformation tagging, and UTF-8-safe truncation. The `llm_summarize` handler in the executor sends `sanitized.text`, ensuring LLM-bound content flows through the sanitizer path. _(updated: 2026-07-21 by fix)_ The user's OWN input (agentic goal/profile context) is no longer irreversibly redacted: a run-scoped `UserInputVault` replaces sensitive values (email, phone, SSN, Luhn-valid card, API-key shapes, auth-shaped URL query values) with indexed resolvable placeholders (`{{user:email:1}}`) that the agent tool middleware resolves back to real values at the execution boundary and re-masks in every model-visible result — tools act on real values, the model only ever sees tokens; the vault path never HTML-parses or query-strips user text, fixing the cheerio `&`/`<` goal mangling and pasted-signed-URL breakage. Per-host overrides are production-ready: `ExtraRedactorTag` now spans `currency_usd`, `date_of_birth`, `case_number`, `account_number`, `iban`, `member_id`, `medical_record_number`, `tax_id`, `passport_number`, and `drivers_license` (context-anchored, low-false-positive redactors), and `DEFAULT_HOST_OVERRIDES` + the packaged `default-host-overrides.yaml` (kept in sync, spec-asserted) ship ~49 entries across banking/payments, brokerage, credit bureaus, health portals/insurers, government, payroll/tax, and auto insurance.

Secret handling is now centralized through the opaque resolver/keychain boundary. `DefaultOpaqueRefResolver` resolves `ValueRef` variants and emits secret-resolution metadata (never secret values), `createKeychainProvider()` returns either a keytar-backed provider or a degraded unavailable provider with one-shot warning logging, and `withSecret` provides best-effort in-memory zeroing semantics for transient secret usage.

Contextual scope enforcement is now a shared core primitive: `packages/core/src/secrets/scope-enforcer.ts` validates plans and rejects mutating behavior in `read-only-data` scope, while the executor wrapper delegates to it and maps violations into executor-level errors.

Audit output is now complete for the FEAT-006 surface. `JsonlAuditLogWriter` appends `agent.jsonl` and `secrets.jsonl` entries, writes scope-summary data into run manifests, and `FilesystemReportBuilder` renders a readable `report.md` from run artifacts. The CI guard `security:static-check` is wired to `scripts/ci-static-check.ts`, which enforces sanitize-before-send and package-boundary restrictions for `pi-agent-core` imports.

Verification coverage includes targeted FEAT-006 suites (12 files / 48 tests) covering sanitizer transforms/profiles/truncation/host overrides, keychain and resolver behavior, scope enforcement, secret zeroing, audit writer/report builder, and static-check fixtures. Property-based tests are in place for sanitizer invariants, query/token stripping, UTF-8 truncation safety, scope validation, and JSONL parseability.
